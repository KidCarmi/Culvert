# Frontend Migration Plan

- **Status**: Proposed (2026-08-21) — implementation begins only after external review of the
  architecture package (ADR-FE-001 + this plan + `FRONTEND-CURRENT-STATE.md` +
  `FRONTEND-FEATURE-PARITY.md` + `FRONTEND-SECURITY-CONTRACT.md`).
- **Shape**: clean parallel replacement. The legacy `static/index.html` keeps serving `/` until
  FE-8 cutover; the new app is developed under `frontend/` and served in parallel during
  migration. No mega-PR; every phase is individually shippable and reversible. No permanent
  dual frontend: FE-9 deletes the legacy file behind an explicit gate.

## 0. Source layout

```
frontend/
├── package.json / package-lock.json / .nvmrc
├── tsconfig.json / vite.config.ts / eslint.config.js / .prettierrc
├── index.html                      # Vite entry; carries __CSP_NONCE__ on its script tags post-build
└── src/
    ├── app/                        # bootstrap, router, providers (query client, toasts, dialogs, session)
    ├── api/                        # ONE typed client + generated types (types.gen.ts from openapi.json)
    ├── design-system/              # tokens.css + primitives (see FE-2 component list)
    ├── layouts/                    # AppShell, auth/setup overlays
    ├── features/
    │   ├── setup/  auth/  dashboard/  traffic/  audit/  diagnostics/  governance/
    │   ├── policy/ authpolicy/ policy-tester/ policylearn/
    │   ├── objects/ (urlcat, catgroups, decprofiles, rewrite, fileblock)
    │   ├── blocklist/  security-scan/  cdr/  decryption/ (exclusions, health)
    │   ├── network/ (upstream, pac)   cluster/   identity/ (idp, users)
    │   ├── certificates/ (certs, ca-mgmt)   settings/   releases/  support/
    │   └── mcp/ (overview, servers, decisions, policies, approvals, health, rollout, management, settings)
    ├── shared/                     # hooks (useSSE, usePoll, useDirtyGuard, useOperation), utils, test helpers
    └── test/                       # vitest setup, MSW-style API fixtures typed from the OpenAPI schemas
```

Feature modules align with product domains; no generic `components/` dump. `frontend/dist/` is
the build output; per ADR-FE-001 OQ-1 (recommended: committed) it is regenerated by CI and
byte-compared — never hand-edited.

## 1. Go embedding & serving design (implemented in FE-1)

Replaces the 3-file assumption in `ui_static.go`:

- **Embed location**: keep the embed in package main, pointed at the build output:
  `//go:embed all:webdist` with the Vite build emitting to `webdist/` at the repo root
  (`frontend/vite.config.ts` `build.outDir: '../webdist'`). Rationale: `static/` keeps serving
  the legacy app untouched during migration; the new embed is additive and deletable. At FE-9,
  `static/` is deleted and `webdist/` remains the single UI embed.
- **Shell**: Vite's `index.html` is post-processed at build time to stamp `__CSP_NONCE__` onto
  every emitted `<script>`/`<link rel=modulepreload>` tag (small Vite plugin, in-repo, no dep).
  `serveUIShell` keeps its per-request `ReplaceAll` contract — now over a ~2 KB shell instead
  of 1.25 MB. `Cache-Control: no-store` on the shell.
- **Hashed assets**: served under `/assets/` with `Cache-Control: public, max-age=31536000,
  immutable`; MIME from a fixed extension table (js/css/svg/png/woff2/map). Vite's
  `manifest.json` is embedded and parsed at startup to (a) verify every referenced asset exists
  in the embed (fail startup, not first click) and (b) locate the entry files for the shell.
- **SPA fallback**: GET/HEAD paths that are not `/api/*`, `/auth/*`, `/healthz`, `/metrics`,
  `/proxy.pac`, `/pac/*`, or an existing asset serve the shell (deep links work). Everything
  reserved keeps today's handlers/404s. Path handling stays on stdlib `http.FS`.
- **Error behavior**: embed-read or manifest-validation failure ⇒ startup error (bare UI port
  refuses with 500 + diagnostic body, never a blank 200).
- **Local development**: `vite dev` proxies `/api`, `/auth`, `/healthz` to a running `culvert`
  (documented `server.proxy` config; cookie flows work because same host via proxy). No Go
  changes needed for dev.
- **Deterministic build**: pinned Node (`.nvmrc` + `engines`), `npm ci`, Vite config with
  stable rollup `output.hashCharacters`/chunk naming, no build-time timestamps or randomness;
  CI gate builds twice and byte-compares `webdist/` (and the deep-gate binary determinism check
  then passes by construction).
- **CI ordering**: with committed dist (OQ-1 A): fast gate adds one job — `npm ci && npm run
  build && git diff --exit-code webdist/ frontend/src/api/types.gen.ts` (drift gate); Go jobs
  are unchanged. Docker/release builds need no Node. If review chooses OQ-1 B instead: Node
  stage in the Dockerfile before the Go builder + build steps in fast-gate hygiene, ci.yml
  test, and deep-gate determinism.

## 2. Phases

Sizes: S ≈ ≤1 engineer-week, M ≈ 1–2, L ≈ 2–4. Every phase's **security gate** includes: CSP
posture unchanged-or-stronger, no new public routes, no secrets in browser storage, ESLint
bans (`dangerouslySetInnerHTML`, `window.confirm/prompt`, `eval`) green. Every phase's
**browser proof** is a Playwright-TS spec recorded in CI (advisory until FE-8, then required).
Every phase lands as multiple focused PRs (listed) — none touches production serving behavior
until its flag/cutover step says so.

### FE-0 — Architecture & parity inventory (this round)
- **Objective**: the five design artifacts; external review; ratify ADR-FE-001 + OQ-1..3.
- **Deliverables**: already produced. **Exit gate**: written review approval. **Rollback**:
  none needed (docs only).

### FE-1 — Build pipeline & embedded serving (foundation)
- **Objective**: `frontend/` scaffold builds a hello-shell deterministically; Go serves it at
  `/app/` (temporary parallel prefix) from the new embed with the full serving contract
  (nonce, hashed assets, SPA fallback under `/app/`, immutable caching, manifest validation).
  Legacy `/` untouched.
- **Dependency**: FE-0 approval. **Size**: M.
- **PR slices**: (1) frontend scaffold + lockfile + lint/type/test CI jobs + dist drift gate;
  (2) Go serving layer (`ui_webdist.go`) + `/app/` route + tests (serving, caching, fallback,
  nonce, missing-asset failure); (3) backend security slice: GAP-1 wildcard C2 fix + GAP-3
  HSTS + GAP-4 PATCH + GAP-5 header-trust gating, each with tests; (4) CI: npm license +
  osv/audit scanning, `.dockerignore`/`.gitignore`/gitleaks entries, `proxy-ui-e2e.yml` path
  filter update.
- **DoD**: build byte-reproducible (CI-proven twice); `/app/` serves with strict CSP
  (`style-src 'self'` — no unsafe-inline from day one in the new app); D0/C1 route locks
  updated by the book.
- **Browser proof**: Playwright-TS loads `/app/`, asserts CSP header + zero console CSP
  violations. **Rollback**: revert the serving PR; legacy UI unaffected (additive). **Exit
  gate**: green determinism + drift gates two consecutive days.

### FE-2 — Design system & application shell
- **Objective**: tokens (seeded from `DESIGN-SYSTEM.md`, both themes, CULVERT identity —
  not generic SaaS), primitives (AppShell, Navigation, PageHeader, DataTable, FormField,
  Dialog, ConfirmationDialog incl. Tier-3 typed-word + two-phase-token variants, StatusBadge,
  HealthCheck, DiagnosticsResult, ConfigDiff, OperationProgress, RollbackBanner, AuditTimeline,
  EmptyState, ErrorState, LoadingState, Toast), the SSE hook, the poll hook
  (route+visibility-gated), the dirty-guard hook, and the typed API client with generated
  types.
- **Dependency**: FE-1. **Size**: L.
- **PR slices**: (1) tokens + AppShell/Navigation + theme persistence; (2) API client + codegen
  + error model + tests; (3) dialog/confirmation family + a11y (focus trap, `inert`, stack,
  reduced motion); (4) table/form/status primitives; (5) hooks (SSE/poll/dirty/operation).
- **DoD**: Storybook-less component test coverage (Testing Library, role/label queries only);
  axe checks on every primitive; per-component bundle budget recorded.
- **Security gate adds**: Radix (if adopted per OQ-2) license/vuln review. **Browser proof**:
  shell renders, keyboard-only navigation across nav + dialog stack. **Rollback**: `/app/` is
  still non-production. **Exit gate**: primitives reviewed against UX-PRINCIPLES MUST rules.

### FE-3 — Setup, auth, session, RBAC navigation
- **Objective**: FE-X01/X02/X08: first-run setup, login/logout with in-band TOTP state machine,

- **Dependency**: FE-2. **Size**: M.
- **PR slices**: (1) setup flow; (2) login/logout/TOTP + 401 interceptor; (3) role guards + nav
  gating + governance data hookup.
- **DoD**: viewer/operator/admin navigation differences proven; pre-setup bootstrap window
  works; parity rows FE-X01/X02/X08 checked.
- **Browser proof**: first-setup, login/logout, expiry, role-differences specs (the 4 required
  flows). **Rollback**: none needed (still `/app/`). **Exit gate**: security review of the auth
  surfaces against `FRONTEND-SECURITY-CONTRACT.md` §1–§2.

### FE-4 — Dashboard & diagnostics (first data-heavy verticals)

### FE-5 — Policy, security, network features
- **Objective**: FE-V16..V26 (policy + draft/commit + staged reorder + tester + authpolicy +

### FE-6 — Cluster, identity, certificates, settings, releases, support
- **Objective**: FE-V27..V30 (idp incl. write-only secret semantics, certs, ca-mgmt incl.

  FE-V35 (support), FE-V36 (settings — decomposed per IA §5 into General / Access & Sessions /

- **Dependency**: FE-5. **Size**: L (~12 PR slices).
- **DoD**: config export/import/rollback truth-telling (dry-run preview, partial-failure,

### FE-7 — Destructive & security ceremonies hardening
- **Objective**: sweep every T1/T2/T3 + MCP-D + 2P ceremony against contract §6; add the two
  new ceremonies (release dispatch T3, cert upload T2); kill the 5 native dialog sites'
  equivalents; failure-injection UX (network error mid-ceremony ⇒ unknown-state rendering).
- **Dependency**: FE-6. **Size**: S–M.
- **Browser proof**: typed-confirm gate cannot be bypassed by Enter; unknown-state path.
  **Exit gate**: ceremony checklist signed against parity §C.

### FE-8 — Parity, hardening, cutover
- **Objective**: serve the new app at `/` (legacy moves to `/legacy/` behind an admin-only
  flag for one release); a11y pass (axe + manual keyboard/SR walkthrough per UX-PRINCIPLES
  §12, contrast audit closing M4); performance budgets enforced in CI; malformed-API-response
  and backend-unavailable behavior; CSP `style-src` tightened in the live header; Playwright
  lane flips from advisory to required for the migrated flows.
- **Dependency**: FE-7 + parity matrix complete. **Size**: M.
- **PR slices**: (1) cutover routing + CSP change; (2) a11y/perf fixes; (3) test-gate flip.
- **DoD**: all 16 required browser flows green against the real binary (embedded bundle, not
  httptest): first setup, login/logout, expiry, role differences, diagnostics, policy
  mutation, failed mutation, destructive confirmation, release operation, SSE reconnection,
  polling cleanup, refresh/deep link, backend unavailable, malformed response, CSP
  enforcement (+ theme). **Rollback**: single revert of the routing PR restores legacy at `/`.
  **Exit gate**: one release cycle at `/` with no P1 regressions.

### FE-9 — Delete legacy frontend & legacy tests
- **Objective**: delete `static/index.html` + `static/chart.umd.js` (+ replace `logo.png` with
  optimized assets), the `/legacy/` route, the ~29 markup-scan tests, the playwright-go
  `uie2e` suite and its npm-driver workaround; update `roadmap/FEATURE-COVERAGE.md`,
  `qualification_manifest_test.go` citations, `static_read_wall_test.go`, D0/C1 counts;
  mark superseded design docs historical.
- **Dependency**: FE-8 exit gate. **Size**: S.
- **Exit gate (deletion gate)**: parity matrix signed 38/38; required browser lane green 2
  weeks; explicit maintainer sign-off recorded in the PR. This is the "no permanent dual
  frontend" enforcement point.

## 4. Performance & dependency budgets (CI-enforced from FE-2)

| Budget | Target |
|---|---|
| Initial JS (shell + app core, gz) | ≤ 250 KB (React+router+query ≈ 60–75 KB gz of it) |
| Initial CSS (gz) | ≤ 40 KB |
| Per-feature lazy chunk (gz) | ≤ 150 KB (charts chunk ≤ 90 KB incl. Chart.js) |
| Images | logo re-exported ≤ 30 KB (SVG or ≤128 px PNG) + proper favicon set; **replaces the 4.16 MB PNG** |
| Interaction readiness (appliance-served, LAN) | shell → interactive dashboard < 1 s on a mid laptop |
| Long-running memory | dashboard soak 30 min: stable heap (no per-tick growth) |
| Dependency count (runtime) | react, react-dom, react-router, @tanstack/react-query, chart.js, (optional radix primitives) — anything else needs written justification |

Feature-level lazy loading is mandatory where it moves the initial budget (MCP suite, charts,
support, cluster). Lockfile pinned; licenses + vulns scanned in CI (FE-1 slice 4); every dep
replaceable (no framework-coupled data layer beyond TanStack Query).

## 5. Risks (ranked) and mitigations

1. **Ceremony fidelity** (MCP rollout, T3 words, 2P rotate) — mitigate: contract §6 checklist +
   dedicated FE-7 phase + failure-injection specs.
2. **Silent capability loss across 38 views/189 endpoints** — mitigate: parity matrix as a hard
   FE-8 gate; per-PR parity-row updates.
3. **Build determinism vs the deep-gate binary comparison** — mitigate: FE-1 proves
   byte-reproducibility before anything else lands; committed-dist keeps Go-only paths inert.
4. **Auth/session edge cases** (TOTP state machine, bootstrap window, SSE re-auth) — mitigate:
   FE-3 security review gate; real-binary E2E.
5. **Policy draft/reorder concurrency semantics** — mitigate: version-fence component tests +
   E2E conflict spec.
6. **Supply chain introduction of npm** — mitigate: minimal pinned dep set, scanning, drift
   gate, no postinstall scripts (`ignore-scripts=true` in `.npmrc`; Playwright browsers via
   the existing OS-level install pattern).
7. **CSP regressions from tooling** (Vite preload polyfills, dev-mode HMR) — mitigate: FE-1
   browser proof asserts zero CSP violations in the production bundle.
