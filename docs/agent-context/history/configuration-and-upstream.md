## Header rewrite rules are read LOCK-FREE (`internal/rewrite`)

[Original lines 241–241](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L241-L241) · `claude-main-L241-L241`

<!-- BEGIN preserved-block: claude-main-L241-L241 -->
- **Header rewrite rules are read LOCK-FREE (`internal/rewrite`)**: `ApplyRequest` and `ApplyResponse` both run on the plain-HTTP forward path (`prepareHTTPForward` before the round trip, `handleHTTP` after it), so every proxied HTTP request paid TWO acquisitions of one process-wide `sync.RWMutex`. `RWMutex.RLock` is an atomic read-modify-write on a single shared word, so — same shape as the `internal/threatfeed`, `internal/connlimit` and IP-filter findings — it was not a constant cost but a throughput CEILING, and it landed hardest in the DEFAULT posture, where NO rewrite rules are configured and the lock guarded an empty slice. Measured (4-core Xeon, `BenchmarkApplyRequest_NoRulesParallel`, n=6 medians): **15.9 ns at GOMAXPROCS=1, 94.6 at 2, 113.7 at 4** — four cores delivered **0.56x** the throughput of ONE (adding cores SUBTRACTED throughput) for a feature that is switched off. Reading an immutable `ruleView` through an `atomic.Pointer` makes it **2.2 / 1.1 / 0.57 ns — flat, scaling 3.9x from 1→4 cores**, and 200x the old four-core figure. The second half is per-rule repeated work: `matchesHost` re-lowercased the rule's PATTERN and re-decided its branch on every request, and lowercased the HOST once per rule rather than once per request. Patterns are now compiled at publish time (`hostMatcher`: `matchAll` / `suffix`+`apex` / `exact`) and the host is lowercased once per call, so a MISSING rule costs a string compare: **1 rule 68.4→20.3 ns, 5 rules 313→31.3, 20 rules 1245→65.0, 50 rules 3100→103** (marginal per-rule cost 62 ns → 1.7 ns). A client may legally spell `Host` with capitals, and `strings.ToLower` allocates when it does — per rule that was **20 allocs / 320 B per request on a 20-rule policy, scaling with the rulebase**; it is now at most 1. Ranging the rules by value also copied the whole 104-byte `Rule` per rule per request (the `rangeValCopy` rule); the view holds `*Rule`. **The contract is one line and it is a SECURITY contract, not a perf one: a published view's rules are never mutated in place, and every mutator of `rules`/`nextID` must call `publishLocked()` before releasing `mu`.** Rewrite rules set and strip headers (the package doc's own example installs `Strict-Transport-Security` and removes `Server`), so a rule added through an unpublishing mutator would be accepted, listed, persisted and audited while never applying to a single request — pinned per mutator by `TestRuleView_EveryMutatorRepublishes` (structural) and `TestRuleView_MutationIsVisibleImmediately` (behavioural), with `TestRuleView_MutatorInventoryIsComplete` failing when a NEW exported method appears unclassified. The no-in-place-mutation half is enforced by the race detector via `TestRuleView_ConcurrentReadersAndWriters`. `mu` and the fields it guards stay the AUTHORITATIVE write-side state, so `SetRules`/`List`/`Add`/`RemoveByID`/`Snapshot` keep their exact prior semantics — including `List`'s pre-existing shallow copy, whose maps alias the stored rules. `(*Rule).matchesHost` is retained as the semantic ORACLE — it compiles the one pattern and asks the live matcher, so the two cannot diverge — and equivalence with the verbatim pre-fix body is pinned by `TestCompiledMatcher_MatchesLegacyBehaviour` plus `FuzzCompiledMatcher`. Gates: `TestBenchGate_ApplyTakesNoRewriterLock` is **structural, not timing-based** (holds the WRITE lock and requires both entry points to answer anyway — deterministic on any hardware, under `-race`, at any load; a ratio gate was rejected for the reason threatfeed's was), with `TestBenchGate_MutatorsStillTakeTheLock` as its control so a pass cannot mean the lock simply stopped being taken, and `TestBenchGate_ApplyAllocsAreFlatInRuleCount` pinning the once-per-call lowercase deterministically via `testing.AllocsPerRun`. Both gates were verified failing against their reintroduced pre-fix shapes.

## Upstream v2 (2F-C) — identity, sealed credentials, eligibility, and the legacy transition (`internal/upstream` + `upstream_v2.go` + `ui_upstream.go`)

- **Upstream v2 (2F-C) — identity, sealed credentials, eligibility, and the legacy transition (`internal/upstream` + `upstream_v2.go` + `ui_upstream.go`)**: every effective entry has a stable id (server ULID for `managed`, `yaml-<authority digest>` for read-only `yaml` entries — 409 `yaml_owned` through the API) and a canonical normalized authority `scheme://[username@]host:port` (`entry.go` `Normalize`/`SpecFromURL`); the effective pool NEVER carries an authority twice across YAML/managed (`ValidateEffective`, refused before publish, surfaced as `duplicate_authority` + count only). Credentials are WRITE-ONLY: `POST /api/upstream/entries/{id}/credential` (`replace` T2 / `clear` T3 with `confirm == id`) seals the password AES-GCM under the node-local `<dataDir>/.upstream_cred_key` (`credkey.go`; the AEAD binds the IMMUTABLE ENTRY ID + authority hash — ciphertext transplanted onto another entry, even one recreated with the same authority, is `mismatch`; NEVER minted on a read or while ciphertext exists anywhere, including a rejected stored document — a missing/unreadable key ⇒ `credentialState: unusable`, an id/authority mismatch ⇒ `mismatch`, neither is unsealed/selected/probed/sent). An existing config.yaml inline credential (`http://u:p@host:port`) is RETAINED in memory only (`ManagedEntry.yamlSecret`, `json:"-"`): read-only `yaml-<digest>` entry, `configured`, probed/selected normally, never persisted/returned/audited/logged, never mutable through the API (409 `yaml_owned`). The scheme grammar is `http|https` ONLY (C4; `socks5` refused on v2/v1/YAML/import/migration). `credentialState` is DERIVED (`none|configured|unusable|mismatch`) and a body asserting it is 400 `credential_state_not_accepted`; an authority change while a credential exists is 409 `credential_bound` (no combined rebind), a delete of a credentialed entry is 409 `credential_present`. Persistence: `admin_settings.json` holds the SEALED `upstream_proxies_v2` document beside a credential-free legacy `upstream_proxies` list (`UpstreamProxiesSaved` sentinel); a stored document that FAILS validation at load is fail-closed AND remembered (`upstreamSetRejected`): managed entries unpublished, `degraded` visible, every managed mutation / v1 replace / import / key mint refused (409 `document_rejected`) and every unrelated save carries the rejected sections forward VERBATIM until repair + restart; a refused YAML seed is tracked separately as `yamlDegraded` and is never cleared by the managed document loading; every managed mutation runs inside `saveAdminSettingsWithOverrides{upstreamMutate}` — validate → persist → publish, so a save failure is a non-2xx with zero mutation — and is revision-fenced (document revision for create + the v1 adapter, entry revision for PUT/DELETE/credential: 428 missing / 409 `stale` + current / 404 `vanished`; a never-persisted document reads as revision 1). A pre-v2 file with userinfo URLs is migrated ONCE at load durable-or-nothing (`upstreamMigrateLegacy`: parse ALL first — parse failure ⇒ `migration.state: degraded/parse_failed`, file untouched, runtime unchanged; key only when a password exists; seal in memory; atomic write of the complete v2 doc + credential-free legacy list; swap after the write). **Behaviour change**: YAML entries now COEXIST read-only with managed ones (a saved empty managed list no longer wipes the YAML seed; a YAML authority also present in a saved list is YAML-owned and skipped). `POST /api/upstream` survives as a CREDENTIAL-FREE v1 adapter only: 409 `credentialed_entries_present` (state gate, checked first) while any managed entry holds a credential, 400 `userinfo_not_allowed`/`invalid_entry` (whole list refused, nothing dropped); the shipped legacy panel uses the per-entry endpoints (switched in the same commit as the restrictions). Config import merges by authority, preserves credentialed entries (omission or a redacted `xxxxx` echo keeps them), refuses a real password (400 `credentials_not_importable`) and is pre-validated before any store mutation. Health is tri-state with a bounded classifier (`probe.go`: `unprobed`, dial/TLS ⇒ `connect_failed`, deadline ⇒ `timeout`, 407 ⇒ `proxy_auth_failed`, 2xx/3xx ⇒ healthy, else `probe_http_error`; credential-ineligible entries are NOT probed; bodies bounded/drained) and every entry carries `health {status, reason, lastProbeAt, source: periodic|manual}` (`probe` = compatibility alias; top-level `probe {configured, interval}` reports the armed loop); eligibility = `(none OR configured+matching id+hash) AND (unprobed OR healthy) AND circuit.Allow()`; modes `no_pool|chained|no_eligible_parent|direct_fallback` with `effective.since` re-stamped only on a transition (the first real fallback transitions + fires the existing `upstream_pool_down` alert once; PX-2 fail-open); `coverage {plainHttp: chained, connect|websocket|socks5: direct, summary: plain_http_only}` (PX-1). **Published proxy generations are IMMUTABLE (correction round 2 — the publication linearization rule)**: every publication (`rebuildLocked`, under `Pool.mu`) constructs a NEW `*Proxy` for every entry and swaps the slice; a `Proxy` that has been published is never written again (`Entry`, `URL` and the credential verdict are fixed at construction), so an in-flight request/probe/attribution slot that selected it holds the COMPLETE old generation and a fresh selection observes the COMPLETE new one — never a mixed binding across a credential replace/clear or a same-authority PUT. Continuity across generations flows ONLY through independently synchronized state: the circuit breaker is shared by pointer (its own mutex) and the probe verdict is copied via the old proxy's own mutex (`Probe()`); a probe result landing on a superseded generation is not carried forward. **Do not reintroduce `up.Entry = e` on a published proxy** — pinned by `internal/upstream/publication_race_red_test.go` (PR1–PR6, run under `-race`). The authenticated proxy URL is constructed ONLY by `authenticatedURL`, reached from exactly two transport selectors — `ProxyFunc` (requests) and `probeProxySelector` (probes), both after the eligibility check — pinned by the AST wall `TestWall_AuthenticatedURLIsConstructedOnlyInsideSelectors`; the probe seam receives `scheme://host:port` only and GET `url` carries no userinfo (username is its own field; the persisted legacy list keeps `user@` for downgrade compatibility). Raw transport errors are never logged/persisted/audited/returned (bounded reason + redacted authority + safe id; `Attribution.Record` logs `reason=` only). Circuit-breaker params stay YAML-owned (remembered from startup `Configure`, which now fails CLOSED on an invalid seed). `initUpstreamProxy` runs even with an empty YAML seed; the SIGHUP reload path stays gated on a non-empty YAML list. Still OFF export/rollback for the sealed document (`upstream_proxies_v2` is an AdminDurable-only Sensitive `configSurfaces` row); the credential-free legacy list stays export/import-only. **The breaker is driven by real request outcomes (CHAOS-11)**: `handleHTTP` attaches an `upstream.WithAttribution` slot to the request context, `ProxyFunc` records the selected proxy, and `Attribution.Record(err)` after the round trip trips/closes that proxy's breaker (`context.Canceled` is never charged — client abort; `DeadlineExceeded` is). The all-parents-down → DIRECT fail-open is observable, not silent: per-request counter + once-per-transition alert (`Pool.noteDirectFallback`), surfaced as `direct_fallback`/`mode` on `GET /api/upstream`(+`/settings`, OpenAPI `UpstreamConfig` — regen `make api-bundle` when touching it), `culvert_upstream_direct_fallback_{active,total}` on `/metrics`, and a red banner in the Upstream panel. An EMPTY pool is the normal direct mode and never counts as fallback. RED matrix: `upstream_v2_red_test.go` (R15–R23, R25–R26, R30–R31, R35–R39, R41–R42). BOTH backup modes archive a SANITIZED `admin_settings.json` (`stripUpstreamCredentialsFromSettings`: `credential` removed, `requiresReplacement:true`), manifest `credentialsOmitted:true`, `.upstream_cred_key` never archived (an archive carrying one is refused; an existing key is preserved in every restore mode).
