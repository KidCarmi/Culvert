## A request header is never a value a root-executed artifact may name (SEC-BOOTSTRAP-HOST-1, `internal/bootstrap/hostsafety.go` + `bootstrap.go` + `ui_cluster.go`)

[Original lines 195–195](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L195-L195) · `claude-main-L195-L195`

<!-- BEGIN preserved-block: claude-main-L195-L195 -->
- **A request header is never a value a root-executed artifact may name (SEC-BOOTSTRAP-HOST-1, `internal/bootstrap/hostsafety.go` + `bootstrap.go` + `ui_cluster.go`)**: `internal/bootstrap` renders the two artifacts a human is told to run with root authority on a brand-new host — the install script the product documents as `curl -fsSL … | sudo bash`, and the `docker-compose.yml` that script downloads — and two of the values interpolated into them came straight off the wire: `r.Host`, and `X-Forwarded-Host` when `proxy.trust_forwarded_headers` is on. The script carried `CP_BASE="{{.CPBase}}"`, and **a double-quoted shell word still performs command substitution**, so a request whose Host header was `cp.example.com$(…)` produced a script that ran the attacker's command, as root, before it did anything else (CWE-78 via CWE-644; the compose half is CWE-94 on a YAML scalar). **Go's own header validation is NOT a mitigation and the belief that it was is what let this survive**: `httpguts.ValidHostHeader` rejects `"`, a backtick, `{` and space, and it ACCEPTS `$ ( ) ' ;` — every byte `$(curl$IFS…;sh)` needs, measured against net/http rather than reasoned about, and `X-Forwarded-Host` is an ordinary header that gets no host-shaped validation at all, so on a trust-forwarded deployment the injection is unconstrained (quotes and backticks included). Three rules now hold. **(1) The primary control is VALIDATION, not escaping, and it is FAIL-CLOSED**: `SafeAuthority` admits exactly a DNS name, an IPv4 literal or a BRACKETED IPv6 literal with an optional decimal port 1-65535, and a request that fails it gets a 400 with NOTHING rendered — not a sanitised authority, because an artifact assembled from a partially-rewritten authority points at a host nobody chose. Escaping-only was the first shape considered and rejected: `'` is one of the bytes a Host header may legally carry, so single-quoting alone is one missing byte away from being no fix at all (pinned by `TestSafeAuthority_Refuses`). The templates single-quote anyway, as the layer UNDER validation. **(2) VALIDATION IS AT THE SOURCE AND RE-CHECKED AT THE SINK.** The handlers validate before a header is written (so a refusal is a clean 400, never a half-written root-executed script), and `RenderScript`/`RenderCompose` re-validate every value and return `ErrUnsafeArtifactValue` with an unwritten stream — the renderer is the last place that can still refuse and must not depend on a caller having done so. `SafeEnrollURL` parses the SHAPE this appliance builds (authority + token + lowercase-hex SHA-256 fingerprint) rather than scanning for dangerous bytes, because "no dangerous byte" has to be re-argued every time the sink changes while "this is the URL we build" stays true; it also closes a second hole, a compose document served with an EMPTY `ca-fp=sha256:` when the cluster CA is not initialised, which would have a fresh DP node trust whatever answers (now 503). **(3) THE TOKEN IS CHECKED BEFORE THE HOST.** Both endpoints sit on `uiAuthMiddleware`'s public allowlist because the enrollment token IS the auth, and the refusal path logs and counts, so ordering the checks the other way would let an unauthenticated caller drive a log line per request — a mitigation for a write-amplification-adjacent defect must not be one (CHAOS-63). The line is additionally rate-limited to 1/min with the magnitude in `culvert_bootstrap_host_refused_total`, and the refusal body never echoes the authority: a misconfigured reverse proxy and a probe are indistinguishable from here, and the response is not the place to confirm which bytes got through. `POST /api/cluster/token` validates BEFORE `GenerateToken`, so a refusal never burns a persisted enrollment token the caller will not see. `Image()` gained the same treatment for the operator-managed `registry_url` (an unsafe override falls back to the built-in default rather than reaching the compose document). **Exploitation needs an intermediary and that is the honest rating, not a reason to leave it**: the requester normally IS the victim, so the cross-actor routes are a cache or CDN in front of the admin port (Host/`X-Forwarded-Host` is then an UNKEYED input and the poisoned entry is served to whoever fetches next) or a reverse proxy that APPENDS to `X-Forwarded-Host` instead of replacing it. High impact (root RCE on a node being provisioned), medium likelihood. Gates: `internal/bootstrap/hostsafety_test.go` — the validator/renderer/structural suite, a DEFECT PROOF that runs the real `bash` to show the double-quoted form expands `$( )` and the single-quoted form does not (so a future "simplification" back cannot read as style), and an EMPIRICAL wall that measures which bytes net/http will actually carry in a Host header and requires every non-`host[:port]` one to be refused, so a Go release that widens that set fails the build instead of quietly re-opening the sink — plus `bootstrap_host_injection_test.go`, which drives the REAL handlers behind a REAL `net/http` server (`httptest.NewRequest` lets a test set an `r.Host` the wire could never deliver, which would make the gate prove less than it claims). Every defect gate was verified failing against the pre-fix shape, with CONTROLS in both suites because the cheapest way to pass all of them is to refuse everything, which would delete one-click DP enrolment. **CODEX ROUND (PR #1458) closed two more, both of the same family.** (a) A REFUSAL AFTER THE HEADERS IS AN EMPTY SUCCESS: `TokenExists` proves only that the token's SHA-256 hash is in the store, so a store that was hand-edited, restored from a legacy format or corrupted can admit a plaintext `SafeToken` refuses — and the renderer's refusal then landed AFTER the 200, so the caller got an empty body and `curl … | sudo bash` silently did nothing, the worst way for a provisioning step to fail because it looks like it worked (measured: 200, 0 bytes). Both handlers now check the token before the response is committed, and answer 500 rather than 404 — the token IS in the store, so "invalid or expired" would send the operator to mint another one that fails identically. This is rule (2) of this note applied to the one value I had reasoned was server-controlled: the sink check was right, its POSITION was not. (b) A VALIDATOR MUST NOT BECOME AN AVAILABILITY REGRESSION: `net.ParseIP` refuses an RFC 4007 zone (`fe80::1%eth0`), which `net.Listen` accepts and an operator may have configured as the gRPC listen address, so the first shape answered 400 to every compose bootstrap on such a node. `parseIPWithZone` admits a zone under a grammar strictly narrower than the host alphabet, on IPv6 only — the same trade `validDNSName` records for the underscore, and the reason both are written down: a byte is added to this allowlist only when the argument "inert in every sink, present in a real deployment" can be made for it. See `docs/operator/dp-bootstrap-artifact-safety.md`.

## Compose operator contract (D1.5)

[Original lines 257–257](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L257-L257) · `claude-main-L257-L257`

<!-- BEGIN preserved-block: claude-main-L257-L257 -->
- **Compose operator contract (D1.5)**: The profile-gated `cli` service in `docker-compose.yml` is the canonical operator path for backup, restore, and cleanup — `docker compose --profile cli run --rm cli <flags>`. Same image as `proxy` (no version-skew). `/backup` (volume `culvert-backups`) is mounted **only** in `cli`; the `proxy` container must not be able to read its own backups. `cli` must not mount `/var/run/docker.sock`. Restore commit is offline-only (`docker compose down` → `run --rm cli --confirm` → `up -d`); backup, restore dry-run, list-leftovers, and cleanup-leftovers (dry-run **and** `--confirm`) are runtime-OK. The legacy `updater` sidecar (superseded by the D1.6 maintenance agent) has since been REMOVED. See `roadmap/D1.5-docker-compose-operator-contract.md` for the design and `docs/operator/docker-compose-backup-restore.md` for the operator-facing how-to.

## Proxy image pin binding (P1.4 — maintenance agent)

[Original lines 258–258](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L258-L258) · `claude-main-L258-L258`

<!-- BEGIN preserved-block: claude-main-L258-L258 -->
- **Proxy image pin binding (P1.4 — maintenance agent)**: The proxy image is selected at the sudo boundary, NOT by an env var. `CULVERT_PROXY_IMAGE` (and its `env_keep`) are removed. Apply/rollback pull a repo-bound pinned digest (`docker pull <proxy_repo>@sha256:<64hex>`) and retag it to the FIXED local tag `culvert/proxy:pinned` (`docker tag … culvert/proxy:pinned`); `docker-compose.yml` proxy+cli resolve that fixed tag (no `${…}` interpolation). The sudoers entries bind the repo as a rendered literal (`{proxy_repo}`, no wildcard) + an exact 64-class hex digest, retag destination fixed — so a compromised `culvert-maint` user can at most run a digest of the one configured repo. `config.proxy_repo` (default `ghcr.io/kidcarmi/culvert`) MUST match `image_allowlist`; `packaging/culvert-maint/install.sh` seeds `culvert/proxy:pinned` BEFORE installing the new sudoers (keep-old-path-until-seed-succeeds). The tag is LOCAL-ONLY: `scripts/install.sh` (quick-start) also seeds it before its `docker compose up` (precedence: `CULVERT_PROXY_SEED_REF` → running-container image → the SIGNED RELEASE CATALOG, the trusted default that resolves the channel to a verified `repo@sha256` digest — NO tag enumeration, NO `:latest`, NO local build in the trusted path; legacy GHCR tag discovery survives only as an explicit, disabled-by-default break-glass via `CULVERT_INSTALL_ALLOW_TAG_DISCOVERY=1`), and `deploy_pinned_seed_test.go` pins the compose↔installer contract so the compose file can never again reference the pinned tag without the quick-start installer seeding it. **Source-free install (deploy bundle)**: the quick-start installer deploys to `/srv/culvert` by default (ALL users — a `0700` home makes the agent-ancestor check skip fail-closed → "Agent unreachable") and never clones the source repo: the runtime image ships `/app/deploy` (compose files + `packaging/` + a static version-stamped `culvert-maint` binary from the Dockerfile `maintbuilder` stage), which `install.sh` extracts from the pinned image via `docker create`/`docker cp`. **Agent-install trust is fail-closed**: the host-root agent binary is trusted from the bundle ONLY after `verify_pinned_image_signature` cosign-verifies the proxy image's registry digest against the pinned tag identity (`MAINT_SIGSTORE_ISSUER`/`MAINT_SIGSTORE_SAN_REGEX`, hardcoded in install.sh — NOT read from the image — and kept byte-equal to `release_identity.env`/the Go constants by `TestInstallScriptPinsSameReleaseIdentity`); a verified image ⇒ `CULVERT_MAINT_SKIP_VERIFY=1` positional install (the source is already verified). If the image cannot be verified (unsigned/main `:latest`, locally built, cosign/registry unavailable) the bundle is NOT trusted and the installer falls back to the cosign-verified signed-release download, then source build. Note the pinned SAN matches only TAGGED releases, so a private-repo/`:latest` host needs a signed version tag (e.g. `CULVERT_PROXY_SEED_REF=…:vX.Y.Z`) for the bundle path. `deploy_bundle_contract_test.go` pins Dockerfile ↔ `.dockerignore` ↔ `install.sh` (compose files must stay IN the docker build context). The git clone remains only as a compat fallback for images predating the bundle — the ghcr.io proxy image must stay publicly pullable. Runner: `ComposePullDigest`/`ComposeTagPinned` (+ `validatePinnedDigestRef`), shared `pullAndTagPinned` used by apply's `pull` and the rollback core's `rollback_pull`; restart uses env-free `ComposeUp`. See `roadmap/D1.6c-pin-value-binding-plan.md`.

- **Release catalog trust (Phase 1 — enforce-by-default)**: Production wiring (`release_wiring.go::loadReleaseManagement`) enters `VerifyEnforce` whenever a trust root is present (baked `bakedReleaseTrustKeysJSON` ∪ `CULVERT_RELEASE_CATALOG_TRUST_KEYS`); with no roots and no override it fails closed → Release Management DISABLED (unsigned catalogs are NEVER auto-trusted). `permissive`/`disabled` are explicit, logged break-glass only via `CULVERT_RELEASE_CATALOG_VERIFY` (resolver `resolveCatalogVerifyMode`). The installer only forwards the env (`release_management_install_contract_test.go` forbids a baked default URL). The legacy Docker updater sidecar has been REMOVED — the maintenance agent (Release Management dispatch → agent `/v1/upgrades/apply`) is now the sole day-2 update path. ## Release catalog pipeline (P2a — `release_gen.go`)

[Original lines 261–261](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L261-L261) · `claude-main-L261-L261`

<!-- BEGIN preserved-block: claude-main-L261-L261 -->
- **Release catalog pipeline (P2a — `release_gen.go`)**: CI generates the official catalog deterministically from release metadata (never hand-edited). `generateReleaseCatalog` produces the exact on-disk shape the P1.2 loader consumes; determinism is load-bearing (compact `json.Marshal`, sorted maps/releases, RFC3339-UTC) because the loader hashes RAW manifest bytes — `TestGenerateReleaseCatalog_Deterministic` is the merge gate. The release-blocking gate `TestReleaseCatalogGate` (env-driven: `CULVERT_RELEASE_GEN_SPEC`/`_OUT`/`CULVERT_RELEASE_EXPECT_DIGEST`) is run by the `catalog-pipeline` job in `ci.yml` against the manifest-list digest the `docker` job pushed; it round-trips the bundle through the REAL `LoadVerifiedCatalog` (no gate/runtime drift), rejects tags, and asserts `list_digest` == pushed digest. The gate signs with an EPHEMERAL in-process ed25519 key (discarded; NOT a trust root) and the attached bundle is UNSIGNED — official keyless (Sigstore-identity) catalog signing + the in-binary verifier are **P2b** (`roadmap/D1.6d-P2-release-pipeline-signing-plan.md`).

## Release catalog keyless trust (P2b-1 — Sigstore-identity verifier)

[Original lines 262–262](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L262-L262) · `claude-main-L262-L262`

<!-- BEGIN preserved-block: claude-main-L262-L262 -->
- **Release catalog keyless trust (P2b-1 — Sigstore-identity verifier)**: A SECOND catalog-signature scheme (`release_catalog_sigstore.go`) that COEXISTS with the ed25519 scheme — never replaces it. A cosign keyless bundle (`index.json.sigstore`: Fulcio cert + sig + Rekor proof) over the RAW index bytes is verified OFFLINE via `sigstore-go` against a baked Sigstore `trusted_root.json` (`//go:embed`; **as of P2b-2a this is the real Sigstore public-good root ⇒ scheme ACTIVE by default**, override/deactivate via `CULVERT_RELEASE_SIGSTORE_TRUSTED_ROOT`) + a PINNED identity (`officialSigstoreIssuer` = the GH Actions OIDC issuer; `officialSigstoreSANRegex` anchored to a tagged release of `KidCarmi/Culvert`'s **`ci.yml`** workflow — exact repo+workflow-file+tag, no wildcard). Identity (cert chain + SAN + issuer) is enforced as part of the verify policy, and the verifier uses the bundle's INTEGRATED Rekor timestamp (never wall-clock), so a checked-in fixture verifies indefinitely and nothing reaches sigstore.dev at runtime (air-gap safe). **Scheme selection** (`verifyIndexSignature`, tri-state `schemeOutcome`): Sigstore first, then ed25519, then the mode-based no-artifact decision — but ONLY a true `fs.ErrNotExist` on a scheme's sidecar falls through; a present-but-unreadable/invalid artifact REJECTS without consulting the other scheme (**artifact-owns-outcome**, closes the strip-one-sig downgrade). Enforce-mode non-emptiness is satisfied by EITHER scheme (`NewTrustStoreWithSigstore`). `/api/releases` surfaces `trust_schemes`. Operator overrides `CULVERT_RELEASE_SIGSTORE_IDENTITY`/`_TRUSTED_ROOT` (break-glass/fork-mirror, public material only); an identity set without a root logs a WARNING and stays inactive. Tests use `ca.NewVirtualSigstore()` (offline). **P2b-1 ships the verifier only — nothing publishes a keyless catalog yet**; release-side keyless signing + the baked official root are **P2b-2**. See `roadmap/D1.6d-P2b-sigstore-identity-trust-plan.md`.

## The release catalog has ONE origin: R2 (`https://catalog.culvertlabs.com`)

[Original lines 264–264](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L264-L264) · `claude-main-L264-L264`

<!-- BEGIN preserved-block: claude-main-L264-L264 -->
- **The release catalog has ONE origin: R2 (`https://catalog.culvertlabs.com`)**. GitHub Pages was retired as a catalog host — `publish-catalog-pages.yml` is deleted, the dual verify is now the R2-only `verify-catalog-publish.yml`, and no workflow may grant `pages: write` or reference `kidcarmi.github.io` (pinned structurally by `TestCatalogOriginIsR2Only`). **The trust contract is unchanged, and that is precisely why the second origin was removable**: integrity comes from the catalog's keyless Sigstore signature verified IN-BINARY against the baked trusted root and the pinned `ci.yml` identity, never from the host — so a second host of the same bytes bought no trust while adding a divergence surface, a second freshness obligation and a second thing to keep serving. The verify workflow applies the SAME checks it used to apply per origin (content match against the release's signed bundle, baked-root served verify that must PASS not skip, availability convergence, the weekly SEC-F5 freshness canary). The baked default client URL (`defaultReleaseCatalogURL`, release_wiring.go) already pointed at R2, so no shipped binary defaulted to Pages; an operator who explicitly set `CULVERT_RELEASE_CATALOG_URL` to the Pages URL must repoint it. **Because R2 is now the only target, a dormant publisher is no longer a safe default**: `publish-catalog-r2.yml` gains an `assert-publication-target` job that FAILS when `vars.R2_PUBLISH_ENABLED` is not `true`, so "nothing was published" is loud instead of a silent green skip. Disabling the Pages *site* in repository settings is a remaining owner action.

[Original lines 265–265](https://github.com/KidCarmi/Culvert/blob/3fcc07e7ab5d1e3bd4d19e6cadc8bb63b682f3af/CLAUDE.md#L265-L265) · `claude-main-L265-L265`

## Release catalog keyless signing (P2b-2b — produce + prove the signed catalog)

- **Release catalog keyless signing (P2b-2b — produce + prove the signed catalog)**: The `catalog-pipeline` job (`ci.yml`) gains `id-token: write` and, on the **tag path only** (`refs/tags/v*`), `cosign sign-blob --yes --bundle index.json.sigstore index.json` (keyless Fulcio+Rekor; no private key), then **proves it end-to-end**: `TestReleaseCatalogKeylessVerify` (env-gated `CULVERT_RELEASE_GEN_VERIFY_SIGSTORE=1`) loads the freshly-signed bundle through the REAL in-binary path (baked root + pinned identity, Sigstore-only enforce store) — so a natural OIDC SAN that doesn't match the pinned `ci.yml` identity FAILS the release. Then `cosign verify` checks the pushed image digest carries the SAME identity (catalog↔image parity). The signed `index.json`+`.sigstore` are attached to the GitHub Release and the `release-catalog-bundle` artifact. **Identity single-source-of-truth**: `release_identity.env` (issuer + SAN regex) is sourced by the CI image-sig gate AND pinned byte-equal to the `officialSigstore*` Go constants by `TestReleaseIdentitySSOT` (no CI↔binary drift). The main-push gate stays the P2a ephemeral-ed25519 round-trip (unsigned, no `.sigstore`). Signing is non-deterministic (per-run cert/timestamp) but covers the deterministic index bytes, so `TestGenerateReleaseCatalog_Deterministic` is unaffected. See `roadmap/D1.6d-P2b2-release-signing-plan.md`.
