## CI Pipelines

Lane architecture (authority: `roadmap/CI-REDESIGN.md`). **The required merge
checks are `✅ Fast PR Gate — APPROVED` and `✅ Deep PR Gate — APPROVED`** —
if a PR is red, look at those two first. The QA/Security gate check names on
PRs are pass-through shells kept for branch-protection continuity; both run
fully on main pushes (and the Security gate on tags + weekly cron).

- `pr-fast-gate.yml` — **Lane A, required on every PR**: fmt/vet/build (+arm64 compile, static assert, tidy check), diff-scoped golangci-lint, the full `-race` + coverage suite on the shared SHARDED engine (stage 5C: `test-race` calls `qa-race-shards.yml` — 4 root shards + non-root lane + independent universe + standalone completeness verdict, egress-audit hardened, the privileged mount-point regression run as root against the same binary and required to PASS) publishing `fast-gate-coverage`, then `coverage-floors` owning both coverage contracts (55% global + per-file floors) on that merged profile; the aggregate requires the race path to be exactly `success` whenever the diff classified as code; dispatch-only `unsharded_audit` / `fault` inputs are qualification paths and a `fault` run never approves, benchgate, govulncheck+gosec, gitleaks (even docs-only PRs), path-gated maint-agent checks, advisory traffic smoke
- `pr-deep-gate.yml` — **Lane B, required-if-triggered** (diff-classified): build-image-once → trivy scan + compose validation, hadolint, staticcheck, determinism (any `*_test.go` change), go-licenses on dep changes, packaging (shellcheck/visudo/systemd)
- `ci.yml` — main/tag path: build, BUILD-ONCE candidate image (main push builds + qualifies one multi-arch image; the tag run reuses it by digest), catalog gate, auto-tag, release + SLSA provenance. Workflow name `CI` is load-bearing (`publish-catalog-r2.yml` triggers on it — do not rename). **Release publication is gated by ONE predicate over ONE manifest** (`.github/scripts/require-release-evidence.sh` + `.github/release-evidence.txt`; `mandatory` rows refuse on failed/cancelled/pending/**skipped**/neutral/absent, `advisory` rows report only) — it was previously hand-written in four jobs and omitted from the fifth, so on a main push `latest`+semver were published and signed 29 minutes before the QA/Security verdict existed (run 35507615339). The `docker` job now pushes only NON-CHANNEL candidate tags (`candidate-<run_id>` — run-scoped because the main-push and tag runs share a commit — plus `sha-<short>`); the evidence-gated `promote-image` job moves `latest`/`main`/semver onto that exact tested digest with `imagetools create`, refusing a digest its own run did not build and applying a re-run rule (tip ⇒ promote, ancestor-of-tip ⇒ skip, divergent ⇒ refuse). Every release asset is staged `draft: true`; `publish-release` (needs release + catalog-pipeline + aggregate-subjects + verify-reproducible + provenance) is the ONLY `--draft=false`, behind `assert-release-complete.sh`. **Cosign keyless SANs are per workflow FILE + ref, not per job** — both new jobs live in `ci.yml` so `release_identity.env` and the baked pin are untouched; moving either into a separate workflow file would break them. A branch `workflow_dispatch` no longer publishes anything. Walls: `release_publication_gating_test.go` + `.github/scripts/test/release-gating-cases.sh`; runbook `docs/operator/release-publication-gating.md`. **Build-once promotion** (`roadmap/CI-REDESIGN.md` §21): the main push's `docker` job decides the version ONCE (`candidate-plan-main.sh`; a re-run reuses the commit's candidate, never rebuilds) and signs a keyless candidate RECORD (in-toto, `…/attestations/release-candidate/v1`: full SHA, repo/workflow/`refs/heads/main`/`push`, run+attempt, version, index + per-platform digests, build inputs), then writes the hint `candidate-commit-<sha>` LAST; `qualify-candidate` runs the candidate itself by digest (platforms, revision, compiler == go.mod pin, `/health` + `culvert-maint -version` on amd64 AND arm64 via QEMU, compose smoke `--no-build`, trivy both platforms) and signs a QUALIFICATION record on main. The tag run builds nothing: `candidate-plan-tag.sh` takes binding → published alias → verified+qualified main candidate → owner-authorized rebuild (`vars.RELEASE_REBUILD_AUTHORIZED_TAG` == the exact tag) → refuse with recovery; it re-qualifies with a fresh DB and `catalog-pipeline` signs the digest IN THE TAG CONTEXT before the release-identity verify. The producer identity (`lib/candidate.sh`, ci.yml@refs/heads/main) is NOT the release identity — never widen `release_identity.env` to accept it. `auto-tag` consumes the candidate's version via `decide-release-version.sh` (lock `release-version-decision`; refuses taken/overtaken/second-version). Every public job depends on `qualify-candidate` with no status-function escape. Walls: `release_build_once_promotion_test.go` + `.github/scripts/test/candidate-promotion-cases.sh`
- `qa-gate.yml` / `security-release-gate.yml` — full functional QA / 10-check security scan on main pushes, tags (security), and weekly cron (security — QA's own weekly schedule is the stage-6B equivalence audit, below); pass-through on PRs. On every QA execution the race+coverage suite runs SHARDED (`qa-race` → `qa-race-shards.yml`: build once, 4 root shards, a non-root lane, a block-universe job, and a verdict that publishes the authoritative `qa-coverage` artifact only after proving completeness on its own); `qa-logic` keeps the whole-module build + `go vet`. The default-false `unsharded_audit` dispatch input additionally runs the pre-5B unsharded race suite and compares it with the sharded run on the same SHA — any covered block the reference reaches and the shards do not FAILS unless pinned in `.github/qa-root-shard-coverage-exceptions.json` (pinned empty by `qa_race_shards_test.go`)
- `ci-perf-report.yml` — **advisory, never evidence** (stage 6B, `roadmap/CI-REDESIGN.md` §17): `workflow_run` after Fast/QA gate runs (non-PR, non-cancelled), weekly trend, dispatch with `run_id`; `actions:read`+`contents:read`, default-branch code, no cache, `GOPROXY=off`. `qa-gate.yml` also runs a **weekly same-SHA equivalence audit** (`schedule`, Sunday 06:23 UTC — the full main graph + unsharded reference + comparison) in its own non-cancelling `qa-audit-<ref>` concurrency group; on audit runs the aggregate `require-success`es `qa-race,qa-coverage,qa-unsharded-audit,qa-unsharded-audit-compare`, so a skipped audit refuses. The audit predicate is written in five places and pinned equal by `ci_perf_report_test.go`. Scheduled runs are never release evidence (`require-gate.sh` reads only `event=push` runs of `main`)
- `codeql.yml` — CodeQL SAST: main pushes, weekly, and PRs touching the proxy/security/release surface
- `code-review.yml` — advisory PR DX: reviewdog inline lint, PR-size, conventional commits
- Nightly/weekly: `fuzz-nightly.yml` (Mon/Wed/Fri coverage-guided fuzzing), `proxy-nightly-e2e.yml` (load), `proxy-weekly-stress.yml`, `proxy-ui-e2e.yml` (playwright), `auth-idp-interop.yml`, `install-lifecycle-e2e.yml` + `maint-agent-*-e2e.yml` (installer/agent e2e — nightly + installer-surface PRs)
