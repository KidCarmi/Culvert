non-commit is provable only with a complete ring, no reset, absence AND a moved fence — and, round 2, HISTORY CONTINUITY: the GET's durable `historyIncarnation` epoch identity — rotated by profile delete/recreate and by a history reset — must equal the one the marker was dispatched in, else the operation stays unresolved and the re-send is refused on both sides (`409 history_incarnation_mismatch`); "currently active" is derived from the committed revision's `storeRevision` + spec digest against the authoritative active store, never from `activeN`; and, round 3, the epoch is a DURABLE TRANSITION OF THE OBSERVED ACTIVE IDENTITY — `LifecycleStore.ObserveActive` runs on every lifecycle read/operation and ROTATES `historyIncarnation` on an observed rewind or same-revision spec replacement by ANY writer (replace import, config rollback, CP→DP snapshot), evidence preserved; `expectedActiveSpecDigest` is an independent publish/rollback fence; a profile delete records `DeletePending` durably BEFORE the active delete and a recreate mints its epoch BEFORE the active create; an identity that could not be made durable is reported "" and the frontend withholds dispatch; and, round 4, ONE PAC WRITER TRANSACTION BOUNDARY — every writer of the active profile store (lifecycle publish/rollback, CRUD, config import, config-version rollback, CP→DP snapshot apply) builds its candidate AND commits it under `pacProfilesAPIMu` (bulk writers via `pacProfilesWriterLock`; lock order `objectReferenceMutationGate` → `configRollbackMu` → `pacProfilesAPIMu`, taken last), and the lifecycle commit is additionally a store-GENERATION compare-and-swap (`ProfileStore.SetIfGeneration`, `409 concurrent_write` when a writer outside the boundary intervened — nothing written); any other writer stamps a fresh random id on each profile whose content it changed and PRESERVES the provenance of every profile it left untouched, so a pool-only or unrelated-profile write never erases a commit's provenance; a document-level identity was NOT sufficient — it was replaced by any unrelated write and a genuine commit was then reconciled as refused); `pacClassifyReconcile` attributes a content-level "committed" verdict to an intent ONLY when the TARGET PROFILE's provenance (`ProfileWriteID`) is its operationId (another writer's identical content ⇒ the durable `concurrent_write` refusal, an unknown identity ⇒ ambiguous, never a guessed commit); `pacWriteConflict` answers `409 concurrent_write` only after the decision record persisted, else the NON-TERMINAL `500 outcome_unknown` + `detail: refusal_not_durable` (the browser keeps its marker, the pending intent stays the durable truth, reconciliation settles it as the same refusal and a repeat of the operationId replays it); and, round 7, AN UNRESOLVED LIFECYCLE INTENT IS SETTLED DURABLY BEFORE ANYONE CHANGES ITS PROFILE — `pacSettlePendingBeforeWrite` runs in every writer (CRUD, config import, config-version rollback, CP→DP snapshot) under `pacProfilesAPIMu` immediately before its write: for every profile whose PRESENCE or content the writer changes — removed, content-changed, and (round 8) candidate-only ADDED, the deterministic union of `pacChangedProfileIDs`; an absent profile can still carry a durable pending first-publish intent — a pending intent is reconciled node-locally (a genuine commit ⇒ durable COMMITTED + history revision; a non-writer ⇒ durable aborted/refused/ambiguous) and the durable truth is re-read; an intent still pending is NOT settled and the writer is refused (CRUD `503 lifecycle_unsettled`) or deferred (import `pac_profiles_not_applied`, rollback error, snapshot next sync) with nothing written — historical authorship is never inferred from current content or the current last writer, and untouched profiles/pools are never blocked); see Architecture Notes); the 2F-F Upstream surface at `/app/network/upstream` — `frontend/src/features/network/upstream/` + `src/api/upstream.ts` — is a typed client over the frozen 2F-C/2F-D upstream v2 contract (`ui_upstream.go`): the credential-free read model through fail-closed decoders (an entry carrying credential material is REFUSED, never rendered), bounded structured refusals rendered as server facts (never re-worded), create fenced on the DOCUMENT revision, update/delete/credential on the ENTRY revision, T2 replace (password once, body only) and T3 clear (exact entry id retyped), admin-only mutations with a complete viewer posture, and NO client-side persistence (the read model is the only truth); and the FRONTEND invariant behind it (2F-F correction round): a 2xx whose media type, JSON or ACTION-SPECIFIC evidence cannot be verified is UNPROVEN — never a success, never a failure — the ceremony closes, the page latches, every mutation and the probe are blocked, the read model is re-read once (a transport death requires the operator's Refresh) and the latch clears only after a genuine read-back; every mutation wrapper binds its 2xx to the action (`entry` identity/authority/state, `deleted`, `ok`+`summary`), and a refusal is a verdict only with its contracted status + typed allowlisted facts (`REFUSAL_CONTRACT`), no server string ever rendered;
