## 6. Follow-up gaps (recorded, not in this PR)

  - *Fix*: badger maps its memtable WAL, value log and new tables through ristretto `z.OpenMmapFile`, which `ftruncate`s new files SPARSE; a store into an unallocated page is a SIGBUS, not an error (upstream ristretto v2.4.2 is unchanged). `third_party/ristretto` is upstream v2.2.0 (module sum + zip sha256 pinned in `CULVERT-PROVENANCE.json`) with ONE change: `fallocate` the writable file when it is created or grown (`z/file.go`, `z/file_linux.go`, new `z/prealloc_*.go`), rolling a failed grow back and removing a file it could not reserve — so the shortage is an error return at create/grow time. `go.mod` replaces the module. Preallocation alone was NOT enough (ASTRA source review, confirmed by test): badger retired the full memtable before allocating its replacement, so a failed allocation left `db.mt` nil and the NEXT write in the same process died on `y.AssertTrue` (`log.Fatalf`). `third_party/badger` is upstream v4.9.6 with the allocation moved first in `ensureRoomForWrite`, `dropAll` and `dropPrefixes` (a failed allocation changes nothing and is retried by a later write) and the value-log offset returned when a grow fails (measured as hygiene: upstream left an unused hole, no acknowledged value lost).
