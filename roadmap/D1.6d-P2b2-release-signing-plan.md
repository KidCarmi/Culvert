# P2b-2 — Official Keyless Catalog Signing + Baked Trusted Root

Status: PLAN (awaiting approval). Builds on P2b-1 (#501, the in-binary Sigstore
verifier — shipped, DORMANT because the baked `trusted_root.json` is empty),
P2a (#500, deterministic generator + release gate), P1.7 (#499, auto-seed),
#498 (enforce-by-default ed25519 verifier).

## Goal

Make the official release pipeline **publish a keyless-signed catalog** and make
a shipped Control Plane **trust it out of the box** — flipping the P2b-1 verifier
from dormant to ACTIVE. After P2b-2 the **technical capability** exists for an end
user running the official image to verify the official catalog through Release
Management with **no operator key management and no private signing key anywhere**
(keyless Fulcio identity + public trust roots only).

**This is NOT the cutover.** P2b-2 does not make catalog dispatch the *preferred*
update path and does not demote the legacy Docker updater — that is Phase 6, gated
on a successful real production catalog-driven update. README/operator wording must
keep the legacy updater as the primary path until then (see "Review outcomes" →
overclaiming). The ed25519 scheme and the legacy Docker updater stay untouched.

This is the step P2b-1 deferred: P2b-1 shipped the ability to *verify* a keyless
catalog; P2b-2 *produces* one and *bakes the public trust material* to check it.

## What ships

1. **Bake the official Sigstore trusted root** — replace the empty
   `trusted_root.json` embed with a pinned Sigstore **`trusted_root.json`**
   (the protobuf-JSON `TrustedRoot` artifact that `root.NewTrustedRootFromJSON`
   consumes — Fulcio CA + Rekor log keys + CT log keys + TSA, NOT TUF
   `root.json` metadata). Public material only. This is what activates the
   scheme (`resolveSigstoreWiring` goes active once the embed is non-empty).
2. **Keyless catalog signing in CI** — in the `catalog-pipeline` job, on the
   **tag path only** (`refs/tags/v*`), `cosign sign-blob --bundle` the generated
   `index.json` → `index.json.sigstore`, and attach it to the published bundle
   (and the GitHub Release). Needs `id-token: write` on that job.
3. **End-to-end keyless verify gate** — after signing, verify the freshly-signed
   bundle through the REAL in-binary path (`LoadVerifiedCatalog` with the baked
   official root + pinned identity, Sigstore scheme) so the gate proves the
   shipped verifier accepts what the pipeline produced. No gate/runtime drift.
4. **Image-signature verify gate (P2a-deferred)** — `cosign verify` the pushed
   proxy image digest against the SAME pinned identity, closing the
   "catalog points at an image built/signed elsewhere" gap.
5. **Docs** — operator/enterprise plan Phase 2b status; README (end users can now
   update via the official catalog); trusted-root rotation/lifecycle doc; fork/
   mirror override guidance.

## Trust kernel (unchanged from P2b-1)

Sign the RAW `index.json` bytes; the index binds every manifest by
`manifest_sha256`, so one signature authenticates the whole catalog. P2b-2 adds
the *producer* side and the *public roots*; the verifier, scheme selection,
identity policy, and freshness/rollback ordering are exactly as shipped in
P2b-1 — no verifier code change beyond activation.

## The baked trusted root (the crux)

- **Artifact:** the Sigstore **`trusted_root.json`** (media type
  `application/vnd.dev.sigstore.trustedroot+json`), obtainable from the Sigstore
  public-good TUF repository target `trusted_root.json` (e.g. via
  `cosign trusted-root create` or the TUF mirror). It contains the **public**
  Fulcio root/intermediate CAs, Rekor log public keys, CT log keys, and TSA
  certs — everything offline verification needs. **No private material.**
- **Embed:** keep the existing `//go:embed trusted_root.json` →
  `bakedSigstoreTrustedRootJSON` (P2b-1). P2b-2 replaces the 0-byte file with the
  pinned snapshot. `go:embed` (not `-ldflags`) — the JSON is large and quoting it
  through the linker is error-prone; embedding a checked-in public file is the
  same trust posture as `static/`.
- **Pinning & lifecycle:** the snapshot is pinned (NOT auto-refreshed via go-tuf
  — that was the P2b-1 dependency-surface decision). Document that Fulcio/Rekor
  key rotation requires a refreshed embed in a later release; operators who need
  a newer root before then set `CULVERT_RELEASE_SIGSTORE_TRUSTED_ROOT`. A new
  `docs/operator/sigstore-trusted-root-lifecycle.md` records: source, pin
  procedure, expiry/rotation concern, and the override.
- **Provenance of the embed:** the file is fetched from the Sigstore public-good
  instance and committed verbatim; the PR records the source URL + the TUF
  snapshot version it came from so a reviewer can reproduce it.

## Identity pinning (already correct in P2b-1)

`officialSigstoreSANRegex = ^https://github\.com/KidCarmi/Culvert/\.github/workflows/[^@]+@refs/tags/v.*$`
issuer EXACTLY `https://token.actions.githubusercontent.com`.

- `[^@]+` does NOT pin a specific workflow filename, so signing may run from the
  existing `ci.yml` — **no workflow rename / overlap-window problem for P2b-2.**
  It DOES pin: this exact repo slug, a workflow under `.github/workflows/`, and a
  **tag** ref (`@refs/tags/v*`). A branch build can never produce a matching SAN.
- Therefore signing MUST run on the tag event (the `release`/tag path), where the
  OIDC SAN carries `@refs/tags/vX.Y.Z`. A main-push `catalog-pipeline` run signs
  nothing (the bundle stays unsigned/audit-only); only the tag run attaches a
  `.sigstore`.

## CI wiring (concrete)

`catalog-pipeline` job (runs on main push OR `refs/tags/v*`):

- Add `permissions: id-token: write` (currently `contents: read`) so cosign can
  mint the keyless OIDC token. Keep `contents: read` for checkout.
- Install cosign (reuse the `sigstore/cosign-installer` pin already used by the
  `docker`/`release` jobs).
- After the existing gate test writes the deterministic `index.json` into
  `CULVERT_RELEASE_GEN_OUT`, add a step **gated on `startsWith(github.ref,
  'refs/tags/v')`**:
  `cosign sign-blob --yes --bundle <out>/index.json.sigstore <out>/index.json`.
- **End-to-end verify step (tag path):** run a Go gate (build WITH the baked
  root) that loads `<out>` via `LoadVerifiedCatalog` with the Sigstore scheme +
  official identity and asserts it verifies — proving the shipped binary accepts
  the freshly keyless-signed bundle. (Env: a new
  `CULVERT_RELEASE_GEN_VERIFY_SIGSTORE=1` switch so the gate test runs the
  keyless round-trip only when a real `.sigstore` is present.)
- Attach `index.json.sigstore` to the uploaded `release-catalog-bundle` artifact
  and to the GitHub Release (the `release` job already attaches release assets).
- **Image-sig verify step (tag path):**
  `cosign verify --certificate-oidc-issuer=<issuer>
  --certificate-identity-regexp=<officialSAN> ghcr.io/kidcarmi/culvert@<digest>`
  using `needs.docker.outputs.proxy_digest`.

Determinism note: `cosign sign-blob` output is NON-deterministic (fresh Fulcio
cert + Rekor timestamp each run) — that's fine. Reproducibility is required only
for `index.json` (P2a `TestGenerateReleaseCatalog_Deterministic`, unchanged); the
signature covers those stable bytes and is verified by identity+artifact, not by
byte-equality.

## Test strategy

- **Offline unit (exists, keep):** P2b-1's `ca.NewVirtualSigstore()` tests cover
  the verifier/identity/scheme logic deterministically — no change.
- **Baked-root smoke (new, offline, deterministic):** a checked-in **real**
  cosign bundle over a FIXED `index.json`, signed ONCE out-of-band against the
  public-good Fulcio/Rekor and committed as a fixture, verified against the baked
  official `trusted_root.json` using the bundle's integrated Rekor timestamp
  (never wall-clock) so it verifies indefinitely. Proves the baked root + a real
  keyless bundle round-trip in-binary, fully offline. (If producing a stable
  committed fixture proves impractical, fall back to the CI-only live smoke and
  document the gap — do not fake it.)
- **CI live smoke (new, tag path):** the end-to-end verify gate above (real
  cosign sign + in-binary verify) on every tagged release.
- **Negative:** wrong-identity / unsigned-in-enforce / tampered-index /
  present-but-invalid `.sigstore` already covered by P2b-1; extend the smoke to
  assert a tampered `index.json` fails against the real bundle.

## Acceptance

- A catalog keyless-signed by the pinned release-workflow identity verifies on a
  shipped CP, online AND air-gapped (baked root, integrated timestamp).
- Wrong identity / unsigned (enforce) / tampered index / present-but-invalid
  `.sigstore` → rejected, `available:false`, no dispatch.
- ed25519 path still works for operator-configured roots (coexistence).
- The pushed proxy image's signature verifies against the same pinned identity.
- `TestGenerateReleaseCatalog_Deterministic` still green; the release-blocking
  gate round-trips through the REAL in-binary verifier (no gate/runtime drift).
- Trusted-root rotation + fork/mirror overrides documented.

## Non-goals (P2b-2)

- NOT the Phase 6 production cutover (one real catalog-driven update + demoting
  the legacy updater) — still gated on a successful prod update.
- Do NOT remove the ed25519 scheme or the legacy Docker updater.
- No go-tuf auto-refresh of the trusted root (pinned snapshot only).
- No GUI surface for the Sigstore overrides (env-only, same documented
  `CULVERT_RELEASE_*` GUI-parity deferral).

## Hard problems for review

1. **Producing a stable committed keyless fixture** for the offline smoke (short
   Fulcio cert vs integrated-timestamp verification) — confirm sigstore-go uses
   the bundle's Rekor timestamp so a checked-in fixture never expires; else
   CI-live-only + documented gap.
2. **Trusted-root size/format** — confirm `root.NewTrustedRootFromJSON` accepts
   the public-good `trusted_root.json` verbatim; pin a specific TUF snapshot
   version and record provenance; watch embed size vs binary bloat.
3. **Signing only on tag, gate runs on main too** — keep the main-push gate
   unsigned (audit) and the signing+verify steps strictly tag-gated; ensure the
   release-blocking gate doesn't require a `.sigstore` on the main-push leg.
4. **Image-sig ↔ catalog identity parity** — both must pin the SAME issuer+SAN;
   factor the regex/issuer into one source of truth (workflow env) to avoid drift
   with the baked `officialSigstore*` constants.
5. **Break-glass / fork** — a fork's tag signatures won't match the baked SAN;
   document `CULVERT_RELEASE_SIGSTORE_IDENTITY` (+ `_TRUSTED_ROOT`) overrides and
   that with neither root nor override the scheme stays dormant (ed25519 or
   disabled still available).

## Slice boundary

Recommended split (safer review; each half independently valuable):
- **P2b-2a:** bake the official `trusted_root.json` + a `TestSigstore_BakedRootCanBeParsed`
  guard + the offline baked-root smoke fixture (activates the scheme; no CI signing).
- **P2b-2b:** CI keyless signing (tag path) + attach `.sigstore` + end-to-end verify
  gate + image-sig verify gate + identity single-source-of-truth.

Single PR is acceptable (feasibility review: ~150 LOC of code; verifier already
shipped) if reviewers prefer.

## Review outcomes incorporated (v2 — 3-agent plan review)

Verdict: all three reviewers said **proceed after folding these in** —
feasibility confirmed BUILDABLE (cosign `--bundle` → `sgbundle.NewBundle` verbatim;
`root.NewTrustedRootFromJSON` accepts the public-good `trusted_root.json` (~50 KB);
determinism preserved since the signature covers stable index bytes; offline
fixture feasible because sigstore-go validates against the bundle's INTEGRATED

Security (fold before merge):
- **SAN-regex breadth (P0-1):** `[^@]+` matches ANY workflow file, so any
  `.github/workflows/*.yml` job with `id-token: write` on a tag could mint a
  catalog-valid identity. The trust floor is still "a tagged build of THIS repo by
  an actor with repo-write," but to keep the signing surface to the one intended
  job, **pin the SAN to the signing workflow file** (`ci\.yml`) —
  `^https://github\.com/KidCarmi/Culvert/\.github/workflows/ci\.yml@refs/tags/v.*$`
  — AND add a CI guard asserting no OTHER workflow requests `id-token: write` on
  tag events. Pinning the filename reintroduces a rename→overlap-window cost
  (document it). This changes `officialSigstoreSANRegex` + the P2b-1 SAN test
  fixtures (safe — scheme is dormant). **Open decision for the maintainer:** pin
  filename (tighter, rename cost) vs keep `[^@]+` (looser, no rename cost) —
  defaulting to PIN unless told otherwise.
- **Identity single-source-of-truth (P0-2):** define issuer + SAN ONCE and consume
  it in (a) the baked `officialSigstore*` Go constants, (b) the catalog
  `cosign sign-blob` step's later verify, (c) the image-sig `cosign verify
  --certificate-identity-regexp`. Add `TestImageAndCatalogIdentityParity` that
  parses the regex out of `ci.yml` and asserts byte-equality with the Go constant,
  so the two can never drift. (Mechanism: a checked-in `release_identity.env`
  sourced by CI + a generator/parity test against the Go constant.)
- **Baked-root provenance + validation (P0-3):** record the exact source
  (`https://tuf-repo-cdn.sigstore.dev/targets/trusted_root.json`, or
  `cosign trusted-root create`) + the TUF snapshot version in the PR; add
  `TestSigstore_BakedRootCanBeParsed` (non-empty embed parses via
  `root.NewTrustedRootFromJSON` and has Fulcio + Rekor + CT material); commit a
  documented fetch/refresh procedure. Confirm it is the Sigstore
  `trusted_root.json` (media type `…trustedroot+json`), NOT TUF `root.json`.
- **Tag-gating (P1-1):** the `cosign sign-blob`, the end-to-end keyless verify,
  and the image-sig verify steps are ALL `if: startsWith(github.ref,
  'refs/tags/v')`. The main-push gate stays the P2a ephemeral-ed25519 round-trip
  (no `.sigstore` required); the release-blocking gate must not demand a
  `.sigstore` on the main-push leg.
- **Downgrade doc (P1-2):** restate in Acceptance that a present-but-unreadable
  `.sigstore` REJECTS (artifact-owns-outcome, no ed25519 fallback).
