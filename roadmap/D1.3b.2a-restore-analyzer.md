# D1.3b.2a — Restore analyzer + mode-aware dry-run + guards

**Status:** implemented in this PR. Destructive commit (atomic `/data` swap, staging directory, `--confirm`) is **D1.3b.2b** — separate, future PR.

This doc captures the analyzer / dry-run contract so D1.3b.2b's commit path can layer on top with a guaranteed-stable input shape.

## CLI

```
culvert --restore <path>
        [--mode {full|trust-root-only|state-only}]   # default: full
        [--accept-dp-reenrollment]                    # informational in dry-run
        [--allow-counter-rollback]                    # informational in dry-run
```

D1.3b.2a does **not** introduce `--confirm`. Every invocation is a dry-run; the analyzer reads current `/data` (read-only) and prints a mode-aware plan. The two acknowledgement flags are accepted but only affect the summary's wording — there is no destructive code path to gate them on yet.

## Mode predicate

Each mode resolves an artifact path to either "from tarball" or "from current /data":

| Artifact | `--mode=full` | `--mode=trust-root-only` | `--mode=state-only` |
|----------|---------------|--------------------------|---------------------|
| `data/ca.bundle` | tarball | tarball | **current** |
| `data/cluster-ca.crt` | tarball | tarball | **current** |
| `data/cluster-ca.key` | tarball | tarball | **current** |
| `data/cluster.json` | tarball | **current** | tarball |
| `data/ui_users.json` | tarball | **current** | tarball |
| `data/config_versions/*` | tarball | **current** | tarball |
| All Tier 2 | tarball | **current** | tarball |

The predicate is implemented as `(restoreMode).fromTarball(tarballPath string) bool` in `restore.go`. Both the analyzer and (eventually) D1.3b.2b's stager use the same predicate — single source of truth.

## What the analyzer computes

`analyzeCommit(files map[string][]byte, dataDir string, opts restoreOpts) (*commitAnalysis, error)`:

| Field | How it's computed |
|-------|-------------------|
| `CurrentCAFingerprint` | SHA-256 of `cert.Raw` from current `/data/cluster-ca.crt` if parseable; empty otherwise |
| `RestoredCAFingerprint` | Mode predicate decides source (tarball vs current); same SHA-256 method |
| `CAFingerprintChanged` | Both non-empty AND different |
| `CurrentEnrolledNodes` | `len(state.Nodes)` from current `/data/cluster.json` if parseable |
| `CurrentUsers` / `RestoredUsers` | Sorted username lists from current and post-merge `ui_users.json` |
| `UsersAddedByRestore` / `UsersRemovedByRestore` | Sorted set differences |
| `TOTPCounterRollbacks` | Sorted usernames where `restored.totp_last_counter < current.totp_last_counter` |
| `FilesFromTarball` / `FilesFromCurrent` | Per-mode file count (manifest.json excluded) |
| `DPGuardActive` / `DPGuardWouldBlock` | Active when CA changes AND nodes are enrolled; would-block when active AND `--accept-dp-reenrollment` not set |
| `TOTPGuardActive` / `TOTPGuardWouldBlock` | Active when any rollbacks; would-block when active AND `--allow-counter-rollback` not set |

Read-only — no `/data` writes, no staging directory created, no temporary files.

## Plan summary shape

```
Restore plan (dry-run, --mode=trust-root-only):

Backup metadata:
  Source:           /tmp/backup.tar.gz
  Schema version:   1
  Created at:       2026-05-01T07:00:00Z
  Culvert version:  v1.2.3

Manifest:
  Files total:         23
  Required (Tier 1):    6
  Optional (Tier 2):   17

Mode-specific merge:
  From tarball:     3 file(s)
  From current:    20 file(s)

Cluster CA:
  Current:    sha256:abc... (4 enrolled DP(s))
  Restored:   sha256:def...
  ⚠ DP re-enrollment required: 4 DP(s) would need to re-enroll.
    Pass --accept-dp-reenrollment to allow commit (D1.3b.2).

Admin accounts:
  Current:   3 (alice, bob, carol)
  Restored:  3 (alice, bob, carol)

TOTP counter rollbacks:
  ⚠ 1 user(s) would have TOTP counter roll back: alice
    Pass --allow-counter-rollback to allow commit (D1.3b.2).

Validation: PASS
  ui_users.json:                3 admin account(s) in restored manifest
  cluster.json:                 0 enrolled DP(s) in restored manifest
  cluster CA cross-validation:  PASS (sha256:def...)

This was a dry-run. No files were written. /data unchanged.
D1.3b.2b will add --confirm to commit a restore.
```

Per-section behavior:
- **Mode-specific merge:** always present.
- **Cluster CA:** four mutually-exclusive states printed depending on guard activity:
  - `⚠ DP re-enrollment required: …` (would block)
  - `ⓘ DP re-enrollment accepted: …` (active + flag set)
  - `CA fingerprint changes; no enrolled DPs affected.` (active but harmless)
  - `CA fingerprint unchanged.` (no change)
- **Admin accounts:** lists current vs restored; shows added/removed when non-empty.
- **TOTP counter rollbacks:** mutually-exclusive states `⚠ would block`, `ⓘ accepted`, or `none`.

## What this PR does NOT do

Per the D1.3b.2a scope decision:

- **No `--confirm` flag, no destructive commit** — D1.3b.2b.
- **No staging directory creation** — D1.3b.2b.
- **No `/data.bak.<timestamp>` creation** — D1.3b.2b.
- **No atomic `/data` swap** — D1.3b.2b.
- **No parent-dir fsync of `/data`** — D1.3b.2b (the swap happens there).
- **No failure-injection seam** — D1.3b.2b.
- **No commit-time guards** — guards are precomputed and surfaced in the dry-run summary; D1.3b.2b will gate the actual swap on the same `commitAnalysis` flags.
- **No backup retention / `.bak` cleanup** — operator's job.
- **No online restore** — operator stops culvert before running.
- **No admin API surface** — CLI-only.
- **No schema migrations** — `schema_version != 1` is rejected (D1.3b.1 contract preserved).
- **No updater / agent work** — out of D1.

## What D1.3b.2b will add on top of this

The analyzer's `commitAnalysis` output is the input to commit-time gating. D1.3b.2b adds:

1. **`--confirm` flag** — without it: today's dry-run. With it: validate → analyze → if any guard `WouldBlock` is true, fail closed; otherwise stage + swap.
2. **Staging directory** — `os.MkdirAll /data.staging.<timestamp>/`; write each artifact via the hardened `atomicWriteFile` (D1.1a) per the mode predicate.
3. **Atomic swap** — `os.Rename(/data, /data.bak.<timestamp>)` + `os.Rename(/data.staging.X, /data)` + parent-dir fsync.
4. **Operator-error recovery messaging** — if commit fails between renames, error names the `.bak` path explicitly: `mv /data.bak.<timestamp> /data`.
5. **Failure-injection seam** — `var commitFailureInjection func() error` for the recovery-message test.
6. **End-to-end commit tests** — backup → restore round-trip; mode-specific commit assertions; atomicity (validation/guard failure → no `/data` write, no `.bak`).

The analyzer signature (`commitAnalysis`) and the mode predicate (`(restoreMode).fromTarball`) are stable across D1.3b.2a / D1.3b.2b. D1.3b.2b will not modify them, only consume them.
