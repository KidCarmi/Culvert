# D1.3b.1 — Restore validation (dry-run only)

**Status:** implemented in this PR. The destructive commit path (`--confirm`, atomic /data swap, modes, risk guards) is **D1.3b.2** — separate, future PR.

This doc captures the dry-run contract so D1.3b.2's commit can layer on top without changing the validator's interface.

## CLI

```
culvert --restore /path/to/backup.tar.gz
```

Validates the tarball against every D1.3b.1 rule and prints a plan summary on success. **Never writes to `/data`.** Exits 0 if all rules pass; exits 1 with a `Restore validation error: …` line on stderr if any rule fails.

Source backup: any `*.tar.gz` produced by D1.3a (`--backup`). Both binaries share the manifest schema (`schema_version: 1`).

Reads `CULVERT_CA_PASSPHRASE` from the environment when validating an encrypted `ca.bundle`. Same env var name as runtime; no separate "restore passphrase".

## Validation rules

All rules run in this order, fail-closed on the first violation. Implementation lives in `restore.go` as a chain of single-purpose functions; tests pin one rule per case.

### 1. Manifest envelope

- `manifest.json` is the **first** entry in the tarball (D1.3a contract).
- JSON parses without error.
- `schema_version == 1` (D1.3b.1 rejects anything else; migration is out of scope).
- `created_at` non-empty.
- `culvert_version` non-empty.

### 2. Bidirectional presence + dedup

- Every `manifest.files[i].path` exists as a tarball entry.
- Every tarball entry (other than `manifest.json`) appears in `manifest.files[]`.
- No duplicate paths in the manifest.

The reverse check defends against tarballs that smuggle extra files past the manifest.

### 3. Per-file checksum / size / mode

For each `manifest.files[i]`:
- `len(body) == size`.
- `sha256(body) == sha256` (hex-encoded).
- `mode` parses as a 4-digit octal string.

### 4. Per-artifact parse (Tier 1 only)

For each Tier 1 artifact present in the tarball, run the same parse logic the live binary uses. Validators reuse byte-level functions where they exist:

| Path | Validator | Underlying logic |
|------|-----------|------------------|
| `data/ui_users.json` | `validateUIUsersJSON` | mirrors `LoadUIUsersFile`: try envelope, fall back to bare-array |
| `data/cluster.json` | `validateClusterJSON` | `json.Unmarshal` into `ClusterState` |
| `data/cluster-ca.crt` + `data/cluster-ca.key` | `(*clusterCA).loadFromPEM` (reused) | includes D1.1f cross-validation of cert public key vs. private key public component |
| `data/ca.bundle` | `validateCABundle` | mirrors `LoadCA`: detect `caMagic`, decrypt if encrypted, `importBundle` to confirm shape |

Failures wrap with the artifact path so the operator knows which file is bad.

### 5. Cluster CA cross-validation

Subsumed by rule 4 (`loadFromPEM` already cross-validates). If both `cluster-ca.crt` and `cluster-ca.key` are present, they MUST form a matched pair. If only one is present, the validator fails with `cluster CA partial pair in tarball`.

### 6. Path-traversal guard

Every tar entry name is split on `/` and any component equal to `".."` aborts with `tarball entry has path traversal: …`. Defense in depth — D1.3a's pack code shouldn't produce such paths, but a hand-crafted tarball can.

## Plan summary

On success, `runRestoreDryRun` writes a fixed-shape plan to **stdout**:

```
Restore plan (dry-run):

Backup metadata:
  Source:           /path/to/backup.tar.gz
  Schema version:   1
  Created at:       2026-05-01T07:00:00Z
  Culvert version:  v1.2.3

Manifest:
  Files total:         23
  Required (Tier 1):    6
  Optional (Tier 2):   17

Validation: PASS
  ui_users.json:                3 admin account(s)
  cluster.json:                 12 enrolled DP(s)
  cluster CA cross-validation:  PASS (sha256:abc...)
  ca.bundle decrypt:            PASS (encrypted)

This was a dry-run. No files were written. /data unchanged.
D1.3b.2 will add --confirm to commit a restore.
```

Lines after `Validation: PASS` are emitted only when the corresponding artifact is present and validated. The shape is intentionally easy to grep / parse.

## What this PR does NOT do

Per the D1.3b.1 scope decision:

- **No `--confirm` flag** — destructive commit is D1.3b.2.
- **No atomic /data swap** — D1.3b.2.
- **No `/data.bak.<timestamp>` creation** — D1.3b.2.
- **No restore modes** (`full`, `trust-root-only`, `state-only`) — D1.3b.2.
- **No DP re-enrollment guard** — D1.3b.2.
- **No TOTP counter rollback guard** — D1.3b.2.
- **No staged merge from current /data** — D1.3b.2.
- **No backup retention / cleanup** — operator's job.
- **No online restore** — operator stops culvert before running.
- **No admin API** — CLI-only.
- **No schema migrations** — `schema_version != 1` is rejected.
- **No updater / agent work** — out of D1.

11 cases in `restore_test.go`, all in-process, race-clean:

| Case | Triggered rule |
|------|---------------|
| `ValidBackup` | none — positive path; asserts no `/data` writes |
| `ManifestMissing` | rule 1 (envelope) |
| `ManifestMalformed` | rule 1 (JSON parse) |
| `UnsupportedSchemaVersion` | rule 1 (schema_version) |
| `ManifestReferencesMissingFile` | rule 2 (forward presence) |
| `TarEntryNotInManifest` | rule 2 (reverse presence) |
| `DuplicateManifestPath` | rule 2 (dedup) |
| `Sha256Mismatch` | rule 3 |
| `CorruptTier1ClusterJSON` | rule 4 (`cluster.json`) |
| `ClusterCAMismatch` | rule 4/5 (`loadFromPEM` cross-val) |
| `EncryptedBundleWithoutPassphrase` | rule 4 (`ca.bundle`) |
| `NoBakOrDataModification` | dry-run safety property |

Helpers: `makeValidBackup` (uses D1.3a's `runBackup`), `repackTarball` (read → mutate → re-pack), `rebuildManifest` (regenerate manifest after file mutations), `assertNoDataMutation` (checks `/data` byte-identical pre/post).

## What D1.3b.2 will add

`--confirm` flag → after validation passes, run a six-step commit:

1. **Stage** — unpack tarball into `/data.staging.<timestamp>/`.
2. **Pre-commit cross-checks** — DP re-enrollment guard, TOTP counter rollback guard, mode-specific merge from `/data`.
3. **Confirmation summary** — print plan including those guards' findings.
4. **Atomic swap** — `os.Rename(/data, /data.bak.<timestamp>)` + `os.Rename(/data.staging.X, /data)` + parent-dir fsync.
5. **Cleanup** — log the `.bak` path; do NOT auto-remove (operator may want it).
6. **Operator-error path** — if commit fails between renames, print explicit recovery instructions (`mv /data.bak.X /data`).

Modes (`--mode=full|trust-root-only|state-only`), risk guards (`--accept-dp-reenrollment`, `--allow-counter-rollback`), and the end-to-end commit tests are all D1.3b.2 work.
