# P2b — Control-Plane Keyless Catalog Trust (Sigstore identity)

Status: PLAN (awaiting approval — no implementation yet). Decision recorded:
**keyless / Sigstore identity**. Builds on #498 (enforce verifier), #499
(auto-seed), #500 (deterministic generator + release gate).

## Goal

Make a shipped Control Plane trust the **official keyless-signed catalog** so end
users can update through Release Management with no operator key management. Add
**Sigstore-identity** verification (Fulcio root + Rekor + a pinned GitHub Actions
workflow identity) as a trust scheme that **coexists with** the existing baked/
operator ed25519 scheme — not a replacement.

This is the change Phase 2 deferred from P2a because it alters the trust model
#498 shipped (baked ed25519 public key) and adds the `sigstore-go` dependency.

## Trust model: two schemes, one kernel

The authentication kernel is unchanged: **sign the RAW `index.json` bytes**;
because the index binds every manifest by `manifest_sha256`, one signature over
one document authenticates the whole catalog. P2b adds a second way to verify
that signature:

| | ed25519 (today, keep) | Sigstore identity (new) |
|---|---|---|
| Trust root | baked/operator ed25519 public key(s) | Fulcio CA + Rekor key (TUF `trusted_root`) + **identity policy** |
| Sig artifact | `index.json.sig` (envelope) | `index.json.sigstore` (cosign bundle: cert+sig+Rekor entry) |
| Verifier | stdlib `ed25519.Verify` | `sigstore-go` bundle verify |
| Identity | "this key" | SAN = `https://github.com/KidCarmi/Culvert/.github/workflows/<release>.yml@refs/tags/v*`, issuer = `https://token.actions.githubusercontent.com` |
| Air-gap | trivial (key baked) | baked `trusted_root.json` + the bundle's offline Rekor SET/inclusion proof |

**Coexistence rule:** in enforce mode the catalog is accepted iff it verifies
under **at least one configured trusted scheme**. Official builds bake the
Sigstore identity policy (+ `trusted_root`); self-hosted operators can keep
ed25519 via `CULVERT_RELEASE_CATALOG_TRUST_KEYS`. Both, either, or neither (→
disabled). permissive/disabled break-glass semantics are unchanged.

## Scheme selection & precedence (fail-closed — exact rule)

Sidecar files: `index.json.sig` (ed25519, existing) and a NEW `index.json.sigstore`
(cosign `--bundle`). Keep them separate rather than cramming a bundle into the
ed25519 envelope. The precise, downgrade-safe resolution (security review):

```
"present"  = file read returns bytes.
"missing"  = read returns fs.ErrNotExist (ONLY this counts as absent).
"unreadable" = any OTHER read error (permission/oversize/corrupt).

1. Sigstore identity policy configured:
   a. .sigstore readable      → verify it; success ⇒ ACCEPT, failure ⇒ REJECT.
   b. .sigstore fs.ErrNotExist → fall through to step 2.
   c. .sigstore unreadable     → REJECT (no fall-through).
2. ed25519 roots configured:
   a. .sig readable            → verify it; success ⇒ ACCEPT, failure ⇒ REJECT.
   b. .sig fs.ErrNotExist      → fall through to step 3.
   c. .sig unreadable          → REJECT.
3. No artifact found for any configured scheme:
   enforce ⇒ REJECT ("no signature present"); permissive ⇒ load+warn;
   disabled ⇒ load (break-glass).
```

**Artifact-owns-outcome invariant:** once a configured scheme's artifact is
present (readable OR unreadable), that scheme decides accept/reject — the other
scheme is NEVER consulted as a fallback. Only a true `fs.ErrNotExist` permits
falling through. This preserves the #498 invariant (present-but-invalid is always
a rejection, never a bypass) and closes the strip-one-sig downgrade vector.

**Verifier ordering (security review):** in `release_catalog_sigstore.go`, validate
the Fulcio cert chain + identity policy (SAN + issuer) BEFORE trusting any other
bundle contents (Rekor proof, etc.), so a malformed/forged bundle cannot bypass
the identity check.

## Components (files)

- `release_catalog_sigstore.go` (new): `sigstoreVerifier` wrapping `sigstore-go`
  bundle verification against a `TrustedMaterial` (baked `trusted_root.json`) +
  an identity policy (SAN regex + issuer). Pure, offline-capable.
- `release_catalog_verify.go`: extend the trust config so `LoadVerifiedCatalog`
  consults the Sigstore scheme; add a `SignatureSource` method for the `.sigstore`
  sidecar. Keep ed25519 path intact.
- `release_wiring.go`: resolve the baked Sigstore identity policy + `trusted_root`
  (linker/`go:embed` for official builds; env override for operators), feed it
  into the trust config alongside ed25519 roots. Enforce-by-default rule extended
  to "any configured scheme present".
- `trusted_root.json` (embedded asset): a pinned snapshot of the Sigstore TUF
  trusted root (Fulcio/Rekor/CTlog), for offline/air-gap verification.
- `.github/workflows/ci.yml`: in the `catalog-pipeline` (tag-release path),
  replace the P2a ephemeral-key gate signature with real `cosign sign-blob
  --bundle index.json.sigstore` (keyless OIDC); attach the bundle; add an
  image-signature-verify gate against the same identity (the P2a-deferred gate).
- Docs: enterprise plan Phase 2b status; README (end-users can now update via the
  official catalog); CLAUDE.md note + new env vars.

## Slicing (two reviewable PRs)

- **P2b-1 — CP verifier (no release change):** add `sigstore-go`, the
  `sigstoreVerifier`, trusted-root bundling, scheme selection + wiring, and tests
  that verify a **fixture** Sigstore bundle (generated once via cosign and checked
  in, or via sigstore-go test material) against a pinned identity. Ships the
  ability to trust a keyless catalog; nothing publishes one yet.
- **P2b-2 — release signing + official root:** CI keyless catalog signing on
  release, attach the `.sigstore` bundle, bake the official identity policy +
  `trusted_root`, image-sig verify gate. After this, an official keyless catalog
  is trusted out of the box.

## Hard problems to resolve in review

1. **`sigstore-go` dependency weight** vs the repo's lean ethos (Dependency
   Obituary threshold 60, govulncheck, SBOM, license scan). Confirm it passes the
   security gate; consider the minimal verification surface (bundle verify +
   identity policy) to limit transitive deps.
2. **Offline / air-gap:** require the published bundle to embed the Rekor SET +
   inclusion proof so verification needs no network to Rekor; bake a pinned
   `trusted_root.json`. Define the refresh/rotation story for that pinned root.
3. **Testing keyless verification deterministically** without live Fulcio: use a
   checked-in fixture bundle + a pinned `trusted_root` snapshot (sigstore-go
   supports verifying against supplied trust material), and a CI smoke that signs
   with real cosign on the tag path.
4. **Identity pinning specifics:** exact SAN regex + issuer; how it survives the
   workflow filename/ref (`refs/tags/v*`); operator override for forks/mirrors.
5. **Enforce-mode composition:** precise rule when both schemes are configured;
   ensure no downgrade path; surface the active scheme on `/api/releases`.

## Review outcomes incorporated (plan v2 — 3-agent plan review)

Verdict: all three reviewers (security / feasibility / scope) said **proceed
after folding these in** — no design rejection.

Security:
- **Exact downgrade-safe composition rule** + `fs.ErrNotExist`-only fall-through +
  artifact-owns-outcome (folded into "Scheme selection & precedence" above).
- **Verify identity before trusting bundle contents** (folded above).
- **Identity-policy specificity:** SAN regex anchored to the full repo slug, no
  wildcard in owner/repo — `^https://github\.com/KidCarmi/Culvert/\.github/workflows/[^@]+@refs/tags/v.*$`
  — issuer EXACTLY `https://token.actions.githubusercontent.com`; releases sign
  only on git tags (never branch builds); document that a workflow-file rename
  needs a policy update + overlap window.
- **Freshness/rollback still applied AFTER** sigstore verification (unchanged
  holder order); keyless ⇒ no private key anywhere (public roots + policy only).

Feasibility (sigstore-go confirmed):
- Offline verify is supported via a baked `trusted_root.json`
  (`root.NewTrustedRootFromJSON`) + `verify.SignedEntityVerifier` with
  `WithCertificateIdentity` and **integrated (bundle-embedded) Rekor timestamps**
  — no runtime network to Fulcio/Rekor. `cosign sign-blob --bundle` is the right
  signer (blob, not attestation).
- **Skip `go-tuf` auto-refresh** (pin a snapshot) to limit transitive deps.
- **Short-lived-cert test-fixture pitfall (P0):** Fulcio leaf certs are ~10 min;
  offline verify checks `cert.NotAfter` against the bundle's integrated timestamp,
  so a checked-in fixture bundle verifies indefinitely — but the test MUST assert
  via the embedded log timestamp, not `time.Now()`. Plan: generate a fixture
  bundle once (cosign against a test CA) + pin a matching test `trusted_root`, and
  add a guard test. Confirm at implementation that sigstore-go uses the integrated
  timestamp (not wall-clock) for the validity window.

Scope / deps / docs:
- **New operator-override env vars (reserve names now):**
  `CULVERT_RELEASE_SIGSTORE_IDENTITY` (issuer+SAN-regex JSON; default baked) and
  `CULVERT_RELEASE_SIGSTORE_TRUSTED_ROOT` (path to a custom `trusted_root.json`;
  default embedded). Operator/break-glass only, env-only — same GUI-parity
  deferral as the other `CULVERT_RELEASE_*` vars (documented, not silent).
- **Embed** `trusted_root.json` via `//go:embed` (module-level var; analogous to
  the existing `static/` embed). Empty/disabled in the open-source build; the
  official root is baked in P2b-2.
- **Trusted-root lifecycle (new doc):** the baked root is a pinned Sigstore TUF
  snapshot, refreshed each release; if it goes stale, operators upgrade or set
  `CULVERT_RELEASE_SIGSTORE_TRUSTED_ROOT`. Document the rotation/expiry concern
  (don't let it go silently stale).
- **Security-gate checklist for the P2b-1 PR:** include `go mod graph | wc -l`
  before/after, confirm Dependency Obituary stays under threshold 60, license
  compatibility (sigstore-go Apache-2.0), govulncheck/trivy/SBOM clean, and any
  go.mod version pins.
- **P2b-1 is verifier-only:** ships no official signed catalog; log a startup
  WARNING if a Sigstore identity is configured without baked/override roots, and do
  not imply end-users can update via the official catalog until P2b-2.

## Non-goals (P2b)

- Do NOT remove the ed25519 scheme (self-hosted operators rely on it).
- Do NOT remove the legacy Docker updater.
- Do NOT perform the Phase 6 production cutover (one real catalog-driven update +
  demoting the updater) — that's a later step gated on a successful prod update.

## Security invariants (carried from the enterprise plan)

- Unsigned official catalogs are never accepted; a present-but-invalid signature
  (either scheme) is always a rejection, never a bypass/downgrade.
- Private signing material never exists (keyless); only public trust roots +
  identity policy are baked/configured.
- Mutable tags are never dispatched; freshness + rollback gates (P1) still apply
  on top of authenticity.
- Air-gap verification must not require reaching sigstore.dev at runtime.

## Acceptance

- A catalog signed keyless by the pinned release-workflow identity verifies on a
  shipped CP (online and air-gapped with the baked root).
- A catalog signed by a DIFFERENT identity, an unsigned catalog (enforce), a
  tampered index, or a present-but-invalid `.sigstore`/`.sig` → rejected,
  `available:false`, no dispatch.
- The ed25519 path still works for operator-configured roots.
