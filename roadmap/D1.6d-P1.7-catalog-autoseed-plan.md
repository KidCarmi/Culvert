# P1.7 — Verified Catalog Auto-Seed (`CULVERT_RELEASE_CATALOG_URL`)

Status: PLAN (follow-up to PR #498 / Phase 1 enforce-by-default).

## Goal

Make catalog seeding **opt-in and automatic**: when an operator sets
`CULVERT_RELEASE_CATALOG_URL` (and trust roots are present), a fresh install with
no catalog on disk fetches the official **signed** catalog from that URL at
Control-Plane startup and reaches `available:true` automatically — **only** after
signature, freshness, and rollback checks pass. Anything wrong ⇒ leave the
existing state untouched and report `available:false` (fail closed). No unsigned
auto-download, ever. Without the URL set, behavior is exactly as today (no fetch).
This removes the manual *crypto/file-placement* step; setting the URL (one env
var) is still the operator's deliberate choice — the installer never bakes a
default URL.

## Non-goals (explicit)

- No crypto verification in shell. The installer does **not** verify catalogs.
- No background refresh ticker / polling (boot-time seed only this slice).
- No GUI config surface yet (env-only, same as the other `CULVERT_RELEASE_*`
  vars; a later GUI slice adds managed config + a manual "refresh" button).
- No air-gap bundle, no mirror repo-rewrite, no agent/dispatch changes.
- Legacy Docker updater stays — untouched.

## Where verification lives (the core decision)

The ed25519 trust roots live in the **Go binary** (baked + `CULVERT_RELEASE_CATALOG_TRUST_KEYS`).
Therefore the download+verify+write MUST happen in the Control Plane process, not
in `scripts/install.sh`. The installer's only job is to **forward the env var**
(`CULVERT_RELEASE_CATALOG_URL`) into the proxy container via compose — trivial
plumbing, no crypto. This is why "installer support for CULVERT_RELEASE_CATALOG_URL"
from the review is implemented as **startup auto-seed in Go**.

## Reused building blocks (already on `main`, already tested)

- `HTTPCatalogProvider.Stage(ctx)` (`release_catalog_http.go`): two-phase verify
  (index signature over raw bytes **before** any manifest fetch), SSRF guard at
  dial-time + redirects, size bounds, conditional GET (304), atomic temp staging
  with cleanup-on-failure. Returns a staged temp dir or `errCatalogUnchanged`.
- `LoadVerifiedCatalog` (`release_catalog_verify.go`): the P1.3 trust boundary.
- The enforce-mode freshness + rollback gate (`release_catalog_freshness.go`):
  `expires_at` required/not-past (5-min skew, future-dated rejected),
  `catalog_version` required (≥1) and ≥ persisted floor at
  `<dataDir>/release_catalog_state.json`.
- `CatalogHolder` + `WithFreshnessEnforcement` (`release_catalog_holder.go`):
  verify + freshness + rollback + atomic publish; load-time and use-time expiry.

## Flow (Control Plane startup, in `loadReleaseManagement`)

```
if CULVERT_RELEASE_CATALOG_URL set AND verifyMode == VerifyEnforce:   # enforce-only gate
   prov = HTTPCatalogProvider(url, trust); prov.SetStageBase(dataDir)  # same-FS staging
   stage = prov.Stage(ctx[timeout])                                    # signed, SSRF-guarded
     - errCatalogUnchanged (304) -> no-op, keep on-disk catalog
     - any error               -> log host-only, no-op (fail closed), keep existing
   # READ-ONLY validation on the staged dir — NO floor write here (see safety note):
   cat = LoadVerifiedCatalog(dirSource(stage), trust)                  # signature (defense-in-depth)
   checkCatalogFreshness(cat, now, skew)                               # expires_at / future-dated
   checkCatalogRollback(cat, readVersionFloor(statePath))             # version >= floor (read-only)
     - any failure -> os.RemoveAll(stage), keep existing (fail closed)
     - success     -> SAFE swap stage -> <dataDir>/release_catalog/:
                        RemoveAll(dst.bak); if dst exists: Rename(dst, dst.bak)
                        Rename(stage, dst)  [on error: restore Rename(dst.bak, dst)]
                        RemoveAll(dst.bak)
# then the existing real holder.Reload() publishes from release_catalog/ and RAISES the floor
# (the authoritative applyFreshnessAndRollback runs once, AFTER the catalog is in place).
```

Key safety properties:

- **Floor raised only after the catalog is in place.** Auto-seed validation is
  READ-ONLY (`checkCatalogFreshness` + `checkCatalogRollback` + `readVersionFloor`);
  it never writes the floor. The single authoritative floor-raise is the real
  `holder.Reload()` AFTER the swap. This closes the "floor outruns on-disk
  catalog if the swap fails" hazard (a raised floor with an unswapped older
  catalog would wedge the next boot at `available:false`).
- **Crash/rename-safe swap.** The old catalog is moved aside to `dst.bak`
  (atomic) before `Rename(stage, dst)`; a rename failure restores it. A good
  on-disk catalog is never lost to a failed seed.

- **Gate before swap.** The candidate is fully verified + freshness/rollback
  checked while still in the temp dir; `release_catalog/` is replaced ONLY on a
  pass. A forged/stale/rollback remote catalog can never clobber a good on-disk
  one.
- **Enforce-only.** Auto-download runs ONLY in `VerifyEnforce` (roots present).
  In break-glass permissive/disabled it is skipped (log a one-line note if a URL
  is set) — we never auto-download an unsigned catalog.
- **Best-effort / non-fatal.** Any failure logs and leaves the prior state; boot
  continues; reads degrade to `available:false`. Same contract as the existing
  startup `holder.Reload()`.
- **Atomic, same-FS swap.** Stage under `<dataDir>` (set `stageBase`) so the
  final `os.Rename` is atomic, mirroring `persistCache`'s pattern.
- **Bounded.** Context timeout (~30s) + optional small retry/backoff; never
  blocks boot indefinitely.
- **Rollback floor shared.** The throwaway-holder validation uses the same
  `statePath`, so the floor it raises is the one the real holder then sees
  (idempotent ≥ check).

## Review outcomes incorporated (plan v2)

From the three-agent plan review:
- **Read-only validation + floor raised by the real holder** (above) — fixes the
  floor-before-swap inconsistency (security/correctness P0).
- **Move-aside backup swap** (above) — fixes the clobber-on-rename-failure window.
- **Enforce-only gate** wraps the whole auto-seed call, not just freshness.
- **`SetStageBase(dataDir)`** added so the final `os.Rename` is same-FS atomic.
- **SSRF defense-in-depth at config parse**: inline `url.Parse` + scheme check +
  `isPrivateHost()` (CodeQL-visible) when reading `CULVERT_RELEASE_CATALOG_URL`,
  on top of the provider's dial-time guard.
- **Host-only logging**: log `u.Host` via `sanitizeLog`, never the full URL
  (avoids leaking userinfo/query). No full URL on any API surface.
- **GUI parity**: `CULVERT_RELEASE_CATALOG_URL` is a read-once provisioning env
  var and joins the documented exception already covering `CULVERT_RELEASE_PROXY_REPO`,
  `CULVERT_RELEASE_CATALOG_TRUST_KEYS`, `CULVERT_RELEASE_CATALOG_VERIFY` — managed
  config + a manual "refresh" button are deferred to the release-management GUI
  slice. Noted, not silently skipped.
- **No config-version snapshot**: auto-seed is a startup mutation with no API
  actor; like the existing startup `holder.Reload()` / `writeVersionFloor`, it
  logs but does not call `saveConfigVersion`. The floor-raise stays the holder's.
- **Opt-in, not "no manual steps"**: goal reworded; acceptance keeps "no URL ⇒
  unchanged from today".
- **Reusable for a later refresh slice**: the provider + `autoSeedCatalog` logic
  is the same code a periodic/manual refresh endpoint will call later.

## Tests

- `autoSeedCatalog`: happy path (verified+fresh ⇒ release_catalog/ populated,
  available:true); forged/unsigned ⇒ no write, fail closed; expired ⇒ no write;
  rollback (lower version than floor) ⇒ no write; 304 unchanged ⇒ no-op;
  network error ⇒ no-op + existing kept; permissive/disabled ⇒ skipped (no fetch).
- Atomic swap: a pre-existing good catalog survives a failed seed (not clobbered).
- URL validation: bad scheme / SSRF private host rejected.
- Contract: compose forwards the env; installer adds no catalog fetch/write.

## Acceptance

- Clean install with a valid signed catalog URL + trust roots ⇒ `available:true`
  with no manual file placement.
- Remove signature / tamper / expire / downgrade the served catalog ⇒
  `available:false`, on-disk catalog (if any) preserved, no dispatch.
- No URL or no roots ⇒ unchanged from today (disabled / available:false).
