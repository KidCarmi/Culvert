# D1.6d / P1.2 — Release Catalog Runtime (Catalog Load + Resolve)

**Status:** DESIGN ONLY. No code, no PR, no endpoint activation. This is the
implementation contract for the **first** runtime slice of the release-management
design (`roadmap/D1.6d-release-management-plan.md`, #389/#363). It turns the
catalog format and resolution model from that plan into a real, testable,
in-process library — and nothing more.

**Scope is deliberately the smallest valuable kernel:** parse the signed-later
index + manifests, structurally validate them, and answer the two queries every
later capability depends on — **forward** `resolve(channel) → pinned digest` and
**reverse** `lookup(running digest) → release`.

> ## The one thing this slice delivers
> **A pure `Resolve` / `Lookup` kernel over a locally-loaded, UNSIGNED release
> catalog.** Forward resolution (channel → release → digest) and reverse mapping
> (running digest → release) are the substrate the entire release layer is built
> on. This slice ships them as a side-effect-free package and defers everything
> else (signing, distribution, agent dispatch, GUI, air-gap) to later slices.

> ## The prime invariant it must not break (restated from #389)
> **The agent stays a low-level, release-agnostic executor.** This slice is
> ENTIRELY Control-Plane-side. It returns a **digest** (`repo@sha256:…`) — the
> agent's native currency — and gives the agent no release/channel/version
> awareness. A test asserts the package needs no agent client.

**Revision note (post-design-review):** this version resolves the two review
blockers before implementation — **B1** (the reverse-map / `RepoDigests`
contract, §3.1) and **B2** (the forward-compatibility policy, §4.0) — plus a set
of hardening contracts (index-integrity warning, repo-equality ownership,
semver-safe ordering, symlink refusal, bounded reads, identifier validation,
one-digest→one-release, raw-byte hashing, CP-only ownership) so the on-disk
format does not have to be revisited later.

## 1. Architecture

```
local catalog dir                in-process (this slice)                 (later slices)
───────────────                  ───────────────────────                 ─────────────
index.json          ─┐
manifests/<id>.json ─┴─▶  LoadCatalog(src) ─▶ Catalog{                   Resolve(ch)──▶ agent image_ref
                          parse → compat-gate    byReleaseID               Lookup(dig)──▶ "Current" badge
                          → validate → hash-bind  byPinnedRef              List()      ──▶ GUI (future)
                          → index }              channels[]                Current(dig)──▶ derived view
```

- **Source is a local directory** (`CatalogSource` abstraction): an `index.json`
  plus one manifest file per release under `manifests/`. There is **no network,
  no registry, no air-gap bundle, no refresh** — distribution is a later slice,
  so the loader is built behind an interface that a future slice can swap. The
  local-dir source **refuses symlinks** and **bounds every read** (§3, §4).
- **`LoadCatalog` is the only I/O.** It parses the index, applies the
  forward-compatibility gate (§4.0), then parses each referenced manifest, runs
  all validation (§4), builds three in-memory maps, and returns an immutable
  `*Catalog`. After load the object is read-only and side-effect-free; all query
  methods are pure.
- **No goroutines, no timers, no caching-with-TTL.** Reload = construct a new
  `*Catalog` (the refresh slice will own swap semantics; not here).
- **CP-only ownership.** In the flat `package main` layout the catalog compiles
  into every binary, but it is a **Control-Plane concern**. Data-plane nodes MUST
  NOT load, expose, or act on a catalog; this slice does not wire it anywhere, and
  the later CP-integration slice owns the CP-only entry point. The package never
  imports an agent client (enforced by an invariant test, §6).
- **Placement:** flat `package main` (per CLAUDE.md), new files
  `release_catalog.go` (model + loader), `release_catalog_resolve.go`
  (resolve/lookup/derive), `release_catalog_test.go`, with a `testdata/release/`
  fixture catalog. Not wired into `controlplane.go`, any admin route, or the
  agent in this slice.

### 1.1 Implementation prerequisites (verify BEFORE shipping reverse-map support)

The reverse map (`Lookup` / `Current` / `byPinnedRef`) is only meaningful if a
*running* container's reported digest can equal a catalog `PinnedRef` (a
manifest-**list** digest). That depends on Docker's `RepoDigests` behavior, which
this plan does not assume — it MUST be **empirically verified before the
reverse-map code is written**:

1. Pull a multi-arch image **by manifest-list digest** (`docker pull
   repo@sha256:<list>`), then `docker image inspect` → record what `RepoDigests`
   contains (expected: the list digest).
2. Pull the **same** image **by tag** → record `RepoDigests` (does a tag pull
   record the list digest or a per-arch descriptor?).
3. Pull **by a per-arch descriptor digest** → record `RepoDigests`.
4. Confirm that the value P1.1 `/v1/status.running_image.repo_digests` surfaces
   for a container the agent deployed (pull-by-list-digest + retag, P1.4) is the
   **list digest** — i.e. it can match a catalog `PinnedRef`.

The findings define the exact `Current()` coverage (§3.1). **If pull-by-list-digest
does NOT record the list digest in `RepoDigests`, the reverse-map key (list
digest) is wrong and the data model must change before code — that is the point
of doing this first.** Document the observed behavior in the implementation PR.

## 2. Data model

Mirrors `roadmap/D1.6d-release-management-plan.md` §6 verbatim; `schema_version`
is the **major** compatibility version (see §4.0).

### 2.1 On-disk (parsed)

```
ReleaseManifest {
    SchemaVersion  int            // MAJOR version; 1 supported (see §4.0)
    ReleaseID      string         // opaque stable key, e.g. "rel_2026_04_v1" (bounded, §4)
    VersionID      string         // human semver, e.g. "1.4.2"
    Severity       string         // "normal" | "critical" | <unknown→treated as "unknown", §4.0/§4.12>
    CreatedAt      time.Time
    Image struct {
        Repo       string         // e.g. "ghcr.io/kidcarmi/culvert" (bare repo)
        ListDigest string         // "sha256:<64hex>" (multi-arch manifest-LIST digest)
        Platforms  []string       // informational only (no per-arch digests; see §3.1 / F7)
    }
    MinUpgradeFrom string         // parsed + retained; NOT enforced in this slice
    ChangelogURL   string         // retained; not fetched
    Notes          string
}

ReleaseIndex {
    SchemaVersion int             // MAJOR version; 1 supported (see §4.0)
    GeneratedAt   time.Time
    Channels      map[string]string          // known keys {recommended, lts, critical}; unknown keys IGNORED (§4.0)
    Releases      []IndexEntry
}
IndexEntry { ReleaseID, VersionID, ManifestRef, ManifestSHA256 string }
```

### 2.2 Derived (in-memory, built at load)

```
Release {                          // a fully-resolved catalog record
    ReleaseID, VersionID string
    Severity   Severity            // typed; known {normal,critical}; any other value retained as "unknown"
    Repo       string              // bare repository, from manifest image.repo
    ListDigest string              // bare "sha256:<64hex>" manifest-LIST digest
    PinnedRef  string              // DERIVED at load: Repo + "@" + ListDigest
                                   //   = "repo@sha256:<64hex>" — the AGENT-FACING image_ref
                                   //   (the agent's native currency; satisfies the shipped
                                   //   validatePinnedDigestRef / image_allowlist SHAPE, P1.4 —
                                   //   repo EQUALITY with the deployment proxy_repo is the
                                   //   dispatch layer's responsibility, see §2.4)
    MinUpgradeFrom, ChangelogURL, Notes string
}

Catalog {
    byReleaseID map[string]Release
    byPinnedRef map[string]string  // PinnedRef ("repo@sha256:…") → ReleaseID  (reverse index)
    channels    map[Channel]string // KNOWN Channel → ReleaseID                (forward index)
    generatedAt time.Time
}

type Channel string // "recommended" | "lts" | "critical"
type Severity string // "normal" | "critical" | "unknown" (forward-compat passthrough)
```

> **Why the reverse index keys on the repo-bound `PinnedRef`, not the bare
> digest.** The manifest stores `repo` and `list_digest` separately (#389 §6),
> but BOTH the agent's apply/rollback contract and P1.1's running-image surface
> speak `repo@sha256:…`: `validatePinnedDigestRef` requires
> `<proxyRepo>@sha256:<64hex>` (P1.4), and `/v1/status.running_image.repo_digests`
> returns `repo@sha256:…` entries. Deriving `PinnedRef = repo@list_digest` once,
> at load, makes forward-resolve hand the dispatch slice a ref the agent accepts
> **without reconstruction**, and lets the reverse map compare directly against a
> running `repo_digests` entry.

### 2.3 One digest → one release (data-model assumption)

A given image **list digest maps to at most one release**. The loader rejects a
catalog with a duplicate `PinnedRef` (F8) so the reverse index is unambiguous.
This deliberately forbids two `release_id`s sharing the same image (re-release,
rebrand, channel split that reuses an identical build). If the catalog ever needs
that, it is a format change handled by a later slice — not silently allowed here.

### 2.4 Repo equality is the dispatch layer's responsibility (NOT this slice)

`PinnedRef` carries the manifest's `image.repo`. The agent (P1.4) binds to the
**deployment's** configured `proxy_repo` literal and rejects any ref whose repo
differs (the §3.1 repo-consistency gate / F6 of the pin plan). This slice
validates only the `PinnedRef` **shape** (§4.14a); it does **not** know the
deployment's `proxy_repo`. Ensuring `catalog.repo == deployment.proxy_repo` — and,
for air-gap, **rewriting the repo prefix** to the local registry while keeping the
(registry-agnostic) digest — is the **dispatch slice's** job. Stated here so that
slice does not assume catalog refs are auto-accepted by every agent.

### 2.5 Query results

```
ResolvedRelease { ReleaseID, VersionID string; Severity Severity; PinnedRef string }
                                                // PinnedRef = "repo@sha256:<64hex>" — handed DIRECTLY to
                                                // the agent's upgrades.apply / rollbacks by a later slice
                                                // (already repo-bound; satisfies validatePinnedDigestRef —
                                                // no per-caller reconstruction; repo-equality is §2.4)

CurrentView { Known bool; ReleaseID, VersionID string }   // !Known ⇒ unknown/custom (§3.1)

ReleaseView { ReleaseID, VersionID string; Severity Severity; Channels []Channel }
                                                // channel badges derived from the channel map; digest-free
```

> **Channels are pointers, not identities** (#389 §2). `recommended`/`lts`/
> `critical` are stored in the index and resolved at load into `channels`.
> **Current** and **Rollback** are *derived*, never stored — this slice derives
> Current (§3.1); Rollback candidates are a later slice.

## 3. APIs

Internal Go package surface — **read-only, no HTTP, no GUI, no agent client**.
All methods are pure and I/O-free after `LoadCatalog`.

| API | Direction | Contract |
|---|---|---|
| `LoadCatalog(src CatalogSource) (*Catalog, error)` | load | Compat-gate (§4.0) + parse + validate + build indexes. **Fail-closed for everything except the closed forward-compatible set** (§4.0): any required-field/shape failure (§4.1–§4.2), digest-shape/ambiguity, hash mismatch, duplicate identity, dangling *required* reference, or unsupported major returns a non-nil error and a nil `*Catalog` (no partial catalog). ONLY the three additive cases (unknown extra fields, unknown channel keys, unknown severity) load by degrading (§4.0). |
| `(*Catalog) Resolve(ch Channel) (ResolvedRelease, error)` | **forward** | Known channel → release → **`PinnedRef`** (`repo@sha256:<64hex>`), handed DIRECTLY to the agent's `upgrades.apply` / `rollbacks` (repo-bound; repo-equality is §2.4). Error if the channel is unknown/absent. A dangling pointer for a known channel cannot occur post-load (§4.3 rejects it). |
| `(*Catalog) Lookup(pinnedRef string) (Release, bool)` | **reverse** | **Exact** match of a repo-bound pinned ref (`repo@sha256:…`) against `byPinnedRef`. `ok=false` for any ref not present. No fuzzy/per-arch matching (§3.1). |
| `(*Catalog) Current(runningRef string) CurrentView` | derived | See §3.1. `{Known:true}` **only** when `runningRef` exactly equals a catalog `PinnedRef`; otherwise `{Known:false}` ⇒ unknown/custom. Caller passes an authoritative P1.1 `running_image.repo_digests` entry — **never** `upgrades.check`'s cache hint (#351 / §10 caveat). |
| `(*Catalog) List() []ReleaseView` | enumerate | All releases + channel badges + severity, **digest-free**. **Semver-safe order** (§3.2). |
| `(*Catalog) GeneratedAt() time.Time` | meta | The index's `generated_at`, for staleness display by a later slice. |

```
type CatalogSource interface {
    // ReadIndex returns the raw index.json bytes, bounded to a maximum size
    // (oversize ⇒ error). Raw, byte-stable bytes — see the raw-byte hash
    // contract (§4.9).
    ReadIndex() ([]byte, error)
    // ReadManifest returns the raw bytes for the manifest named by an
    // IndexEntry.ManifestRef (a bundle-relative bare name, NOT a path the caller
    // can escape). The local-dir impl joins it under manifests/, REFUSES
    // symlinks (Lstat/O_NOFOLLOW), rejects separators/traversal, and bounds the
    // read size (oversize ⇒ error).
    ReadManifest(ref string) ([]byte, error)
}
```

The only concrete `CatalogSource` in this slice is a **local directory** reader
(symlink-refusing, size-bounded). A registry/bundle source is a later slice and
implements the same interface.

### 3.1 `Current()` coverage contract (B1 — exact-match only)

`Current(runningRef)` returns **`{Known:true}` if and ONLY if `runningRef`
exactly equals a catalog `PinnedRef`** (a manifest-list digest, repo-bound).
Every other input is **`{Known:false}` ⇒ unknown/custom**, which is a normal,
expected state, **not** an error. Specifically, the following are Unknown/Custom:

- a **per-arch descriptor digest** (not the manifest-list digest),
- an image pulled **by tag** whose reported digest is not a catalog `PinnedRef`,
- a **legacy / pre-catalog install** (any image deployed before the catalog
  existed),
- any running digest **not present in the catalog** at all.

> **This slice makes NO claim of universal "Current" detection.** It detects
> exactly the catalog-deployed list digests it indexes. Reconciling a per-arch or
> tag-resolved running digest back to a manifest-list release requires a registry
> query and is **deferred to the distribution slice** (§7, F7). The §1.1
> prerequisite verification fixes which real-world deployment modes fall into
> Known vs Unknown; the implementation PR records the result. Do not widen this
> contract without that data.

### 3.2 Ordering policy (semver-safe)

`List()` MUST order by **parsed semantic version** of `VersionID` (descending,
newest first), with `ReleaseID` as a stable tiebreaker — NOT a lexical string
sort (a string sort places `1.10.0` before `1.9.0`). If a `VersionID` fails to
parse as semver it is rejected at load (§4.11), so ordering never sees a
non-semver value. The order is deterministic and pinned by a test.

## 4. Validation rules

### 4.0 Forward-compatibility policy (B2)

The catalog is a distribution contract: a newer, legitimately-produced catalog may
reach an **older** binary (air-gap bundle / OVA). Validation is therefore split
into **fail-closed** rules (a violation means "this catalog is unsafe — refuse it
entirely") and **forward-compatible degradation** (an unrecognized-but-additive
input loads, with the unknown part ignored or marked).

The rule is **asymmetric and closed on the tolerant side**: a catalog loads
through degradation **ONLY** for the three additive cases below; **everything
else fails closed** (the later §4.1–§4.2 validation rules remain authoritative).

**Forward-compatible — load SUCCEEDS, degrade gracefully — EXACTLY these three
cases (a closed set; nothing else degrades):**
- **additive compatible extensions** — unknown/extra JSON fields within a
  supported major are tolerated (§4.16). Producers add optional fields without
  bumping major. (This is the ONLY thing "unknown field" buys — it does NOT
  excuse a malformed or missing *required* field.)
- **unknown channel keys** — a `Channels` key outside `{recommended, lts,
  critical}` is **IGNORED** (dropped from `channels`; the catalog still loads).
  `Resolve(<that channel>)` simply errors as "unknown channel." (A *known* channel
  key with a dangling target is still fail-closed.) (§4.3, F14)
- **unknown severity values** — a `severity` outside `{normal, critical}` is
  **NOT** rejected and is **NOT** silently coerced to `normal` (which could hide a
  real criticality) or to `critical` (false alarms). It is retained and typed as
  `Severity("unknown")` — a non-actionable value a later GUI renders neutrally and
  surfaces as "unrecognized severity" so an operator notices. (§4.12, F13)

> **Severity bias rationale:** because severity drives operator-facing prominence,
> the safe degradation for an *unknown* value is "neither suppress nor escalate" —
> never map it to `normal` (hides danger) or `critical` (cries wolf).

**Fail-closed — reject the WHOLE catalog (load returns error, nil catalog) for
EVERYTHING NOT in the closed forward-compatible set above.** In particular this
includes **all required-field presence and shape validation in §4.1–§4.2** — a
malformed or missing *required* field is NEVER reclassified as "additive". The
notable classes (non-exhaustive; the authoritative rules are §4.1–§4.2):
- **required-field / shape failures (§4.1–§4.2)** — missing/empty `release_id` or
  `version_id`; non-semver `version_id` (§4.11) — `List()` ordering depends on it;
  malformed `generated_at`/`created_at` (§4.2/§4.15); bad `image.repo` shape
  (§4.13) or out-of-bounds `release_id`/channel key (§4.7); bad `manifest_ref`
  (§4.5) or `manifest_sha256` (§4.6); index/manifest cross-mismatch (§4.10);
- **digest ambiguity / bad shape** — a `list_digest` / `PinnedRef` that is
  malformed or duplicated (§4.14, §4.14a, F8);
- **hash mismatch** — `sha256(manifest) != manifest_sha256` (§4.9, F4);
- **duplicate identity** — duplicate `release_id` or duplicate `PinnedRef`
  (§4.4, F8);
- **dangling REQUIRED reference** — an index entry whose manifest is missing
  (F3), or a **known** channel key pointing to an absent `release_id` (§4.3, F5);
- **unsupported MAJOR schema** — `schema_version` absent/`< 1` or **greater than
  the highest supported major** (currently `1`) (§4.1, F2). A binary cannot
  safely interpret a major it does not know.

> **The compat gate is NOT a substitute for validation.** The checklist runs
> "compat-gate → validate" only because the gate does two narrow things: (a)
> decide the supported major, and (b) arm the three degradation behaviors above.
> Every §4.1–§4.2 required-field and shape rule still executes afterward and fails
> closed; the gate never short-circuits or downgrades them.

### 4.1 Index

1. `schema_version` is the **major** version: reject if absent, `< 1`, or
   `> maxSupportedMajor` (=1) — see §4.0. (Equal to a supported major ⇒ proceed;
   unknown *minor* deltas surface only as unknown fields, tolerated by §4.16.)
2. `generated_at` parses as RFC 3339.
3. **Channel handling (§4.0):** for each `Channels` entry — if the **key is
   known** (`recommended`/`lts`/`critical`), its value MUST reference a
   `release_id` present in `Releases` (dangling ⇒ **reject**, F5); if the **key is
   unknown**, the entry is **ignored** (F14). Two known channels may point to the
   same `release_id` (e.g. `recommended == critical`) — allowed.
4. `Releases` is non-empty (F10); `release_id` and `version_id` non-empty;
   `release_id` unique (no duplicate, F8); no duplicate derived `PinnedRef` once
   manifests are loaded (digest ambiguity, F8).
5. Each `IndexEntry.ManifestRef` is a **bare name** (no `/`, `\`, `.` traversal).
   The local-dir source additionally **refuses symlinks** and rejects escapes
   (§3, F9, F11).
6. Each `IndexEntry.ManifestSHA256` is `^[0-9a-f]{64}$`.
7. **`release_id` and channel keys are bounded** (printable ASCII, no control
   chars/whitespace/newlines, length ≤ 128) — `release_id` is otherwise opaque,
   but an unbounded value is a log/SIEM/GUI-injection vector once it flows
   downstream. `version_id` is constrained separately as semver (§4.11).

### 4.2 Manifest (per release)

8. `schema_version` major-gated identically to the index (§4.1.1 / §4.0).
9. **Hash binding (integrity, NOT authenticity) — raw-byte contract:**
   `sha256(<raw manifest file bytes as read>) == IndexEntry.ManifestSHA256`,
   compared as lowercase hex. The hash is over the **exact bytes on disk** — the
   loader MUST NOT re-marshal/canonicalize before hashing, and the producer MUST
   ship byte-stable files. (This keeps the P1.3 index-signature chain anchored to
   the same representation — see the note below.) Mismatch ⇒ reject (F4).
10. `release_id` / `version_id` equal the index entry's values (cross-consistency,
    F-cross). A swapped manifest is caught here.
11. `version_id` matches a semver shape (`^\d+\.\d+\.\d+(?:[-+].*)?$`) AND parses
    for ordering (§3.2).
12. `severity` is parsed: `{normal, critical}` are known; any other value is
    retained as `unknown` (§4.0/§4.12) — load is NOT rejected.
13. `image.repo` is a bare repository (no `@digest`, no tag) — reuse the same
    shape rule as `config.proxy_repo` (P1.4): `^[A-Za-z0-9][A-Za-z0-9._/:-]*$`,
    no `:` after the final `/`.
14. `image.list_digest` matches `^sha256:[0-9a-f]{64}$`.
14a. **Derived `PinnedRef` is agent-shape-acceptable:** the composed
    `image.repo + "@" + image.list_digest` MUST match
    `^<image.repo>@sha256:[0-9a-f]{64}$` — exactly the agent's
    `validatePinnedDigestRef` / `image_allowlist` **shape** (P1.4). This guarantees
    the *shape* a catalog-resolved ref needs; **repo-equality** with the
    deployment's `proxy_repo` is the dispatch slice's responsibility (§2.4).
15. `created_at` parses RFC 3339. `min_upgrade_from`, if present, matches the
    semver shape (retained, **not enforced** — a later slice).
16. Unknown/extra fields are **tolerated** within a supported major (§4.0/§4.16);
    all listed required fields must be present and well-formed.

> **§4.9 is a content hash, NOT a signature — and the INDEX itself has no
> integrity protection in P1.2.** Manifest hash-binding catches a corrupted or
> drifted manifest, but a bit-flip in the **index** that stays structurally valid
> — e.g. a channel pointer flipped to a *different existing* `release_id` — is
> **undetectable** until the index is signed. Hashing is worthless against a
> tampering attacker (who can rewrite both the manifest and its recorded hash).
> The trust anchor — a **signature over the index** — is a **later slice (P1.3)**.
> Until then the catalog is integrity-checked at the leaves only; do NOT describe
> or rely on P1.2 as authenticated. (#389 §7.)

## 5. Failure modes

| # | Condition | Behavior |
|---|---|---|
| F1 | Index missing / unreadable / not JSON | `LoadCatalog` returns an error; nil catalog. |
| F2 | `schema_version` absent / `< 1` / **> max supported major** | reject (unsupported major, §4.0). A supported major with unknown minor fields loads (§4.16). |
| F3 | Manifest referenced by the index is missing/unreadable | reject — dangling required reference (the index promised it). |
| F4 | `manifest_sha256` mismatch (§4.9) | reject — distinct integrity error kind so the P1.3 signing slice can layer cleanly. |
| F5 | **Known** channel key → absent `release_id` (dangling) | reject (dangling required reference, §4.3). |
| F6 | Running digest maps to no release (`Lookup`/`Current`) | NOT an error — `{Known:false}` ⇒ unknown/custom (§3.1). The expected state for legacy/pre-catalog/foreign images. |
| F7 | **Per-arch / tag-resolved running digest vs list digest** | `Current` returns Unknown (§3.1): the running entry may be a per-platform descriptor while the manifest carries the manifest-LIST digest. **Known limitation** — per-arch→list reconciliation needs a registry query and lands with the distribution slice. The §1.1 prerequisite fixes which deployment modes are affected. |
| F8 | Duplicate `release_id` OR duplicate `PinnedRef` | reject — duplicate identity / digest ambiguity (§4.4). |
| F9 | `manifest_ref` separator / traversal | reject (§4.5). |
| F10 | Empty catalog (no releases) | reject — a configuration error, not a valid state. |
| F11 | **Symlinked** index or manifest in the local-dir source | reject — the source refuses symlinks (§3, §4.5). |
| F12 | Index or manifest **exceeds the read size bound** | reject — bounded read (§3). Protects the (later) network/bundle sources too. |
| F13 | **Unknown `severity`** value | **load SUCCEEDS** — retained as `Severity("unknown")`, neither suppressed nor escalated (§4.0/§4.12). |
| F14 | **Unknown `Channels` key** | **load SUCCEEDS** — the key is ignored/dropped from `channels`; `Resolve(<it>)` errors as "unknown channel" (§4.0/§4.3). |
| F-cross | Manifest `release_id`/`version_id` ≠ the index entry's | reject — cross-consistency (a swapped/mismatched manifest), §4.10. |

Fail-closed failures yield **no** catalog (never a partial one). Forward-compatible
cases (F13/F14, plus unknown additive fields) load and degrade.

| validate | `release_id` with control chars / over-length | reject (§4.7). |
| validate | index/manifest `release_id`·`version_id` cross-mismatch | reject (F-cross / §4.10). |
| hash | **raw-byte** contract | a manifest whose bytes hash to `manifest_sha256` loads; re-indenting the file (same JSON, different bytes) ⇒ hash mismatch ⇒ reject (proves no canonicalization) (§4.9). |
| resolve | `Resolve(recommended/lts/critical)` | returns the right `PinnedRef` + `VersionID` + `Severity`. |
| resolve | **`Resolve().PinnedRef` is repo-bound** | matches `^<repo>@sha256:[0-9a-f]{64}$` (agent shape, §4.14a), NOT a bare `sha256:…`. |
| resolve | `Resolve(unknown channel)` | error. |
| reverse | `Lookup(known PinnedRef)` | release, `ok=true`. |
| reverse | `Lookup(unknown ref)` | `ok=false`. |
| current | `Current(exact PinnedRef)` | `{Known:true}` (§3.1). |
| current | **`Current(per-arch / tag / legacy / foreign digest)`** | `{Known:false}` — exercises every Unknown/Custom class in §3.1 (B1). |
| enumerate | `List()` **semver order** | `1.10.0` sorts above `1.9.0` (parsed semver, NOT lexical); deterministic; digest-free (§3.2). |
| invariant | **no agent awareness** | package imports/needs no agent client; `ResolvedRelease.PinnedRef` is the only agent-facing value. |
| invariant | **integrity ≠ authenticity** | a hash-valid-but-unsigned catalog still loads (signing not yet enforced) — guards against treating §4.9 as a trust boundary. |

Determinism: `LoadCatalog` is deterministic for a given source; `List()` order is
pinned (no map-iteration order leaking into outputs).

## 7. Explicit non-goals (deferred to later slices)

This slice does **none** of the following, by design:

- **Signatures / authenticity** (#389 §7) — *no signatures yet*. §4.9 is a hash
  only; the **index-signature trust anchor is a separate slice (P1.3)**, and the
  index has no integrity protection until then (§4 note).
- **Catalog distribution / refresh** — *no network*: no registry fetch, no
  CP-hosted catalog endpoint, no polling/TTL/hot-swap. Local directory only.
- **Air-gap bundle / OVA** (#389 §8) — *no OVA work*. (The CatalogSource interface
  + repo-rewrite ownership (§2.4) are positioned so the air-gap slice lands
  additively.)
- **GUI / admin API** — *no GUI*: no operator-facing surface, no release selector,
  no badges rendered. `List()` returns a view a future slice will present.
- **Agent changes & upgrade dispatch** — *no agent changes*: this slice never
  calls `upgrades.check` / `upgrades.apply` / `rollbacks`. It only **produces**
  the repo-bound `PinnedRef` a later slice will hand to the already-shipped agent
  APIs (with repo-equality enforced there, §2.4).
- **CP→DP propagation** — the catalog is **not** added to `ConfigSnapshot` or
  synced to data-plane nodes (CP-only, §1).
- **Rollback candidates** (#389 §4) and **`min_upgrade_from` enforcement**
  (#389 §13 F5) — parsed/retained but not computed/enforced.
- **Per-arch → manifest-list digest reconciliation** (F7/§3.1) — needs a registry
  query; lands with the distribution slice.
- **Audit** (#389 §12) — no release-level audit records here.

**Natural slice order after this one:** (1) catalog distribution + refresh →
(2) index signature verification (P1.3) → (3) CP→agent upgrade dispatch via
`Resolve` (with repo-equality, §2.4) → (4) rollback-candidate computation →
(5) GUI release selector.
