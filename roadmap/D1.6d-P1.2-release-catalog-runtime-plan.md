# D1.6d / P1.2 — Release Catalog Runtime (Catalog Load + Resolve)

**Status:** DESIGN ONLY. No code, no PR, no endpoint activation. This is the
implementation contract for the **first** runtime slice of the release-management
design (`roadmap/D1.6d-release-management-plan.md`, #389/#363). It turns the
catalog format and resolution model from that plan into a real, testable,
in-process library — and nothing more.

**Scope is deliberately the smallest valuable kernel:** parse the signed-later
index + manifests, structurally validate them, and answer the two queries every
later capability depends on — **forward** `resolve(channel) → pinned digest` and
**reverse** `lookup(running digest) → release`.

> ## The one thing this slice delivers
> **A pure `Resolve` / `Lookup` kernel over a locally-loaded, UNSIGNED release
> catalog.** Forward resolution (channel → release → digest) and reverse mapping
> (running digest → release) are the substrate the entire release layer is built
> on. This slice ships them as a side-effect-free package and defers everything
> else (signing, distribution, agent dispatch, GUI, air-gap) to later slices.

> ## The prime invariant it must not break (restated from #389)
> **The agent stays a low-level, release-agnostic executor.** This slice is
> ENTIRELY Control-Plane-side. It returns a **digest** (`repo@sha256:…`) — the
> agent's native currency — and gives the agent no release/channel/version
> awareness. A test asserts the package needs no agent client.

---

## 1. Architecture

```
local catalog dir                in-process (this slice)                 (later slices)
───────────────                  ───────────────────────                 ─────────────
index.json          ─┐
manifests/<id>.json ─┴─▶  LoadCatalog(src) ─▶ Catalog{                   Resolve(ch)──▶ agent image_ref
                          parse → validate →    byReleaseID               Lookup(dig)──▶ "Current" badge
                          hash-bind → index }   byListDigest              List()      ──▶ GUI (future)
                                                channels[]                Current(dig)──▶ derived view
```

- **Source is a local directory** (`CatalogSource` abstraction): an `index.json`
  plus one manifest file per release under `manifests/`. There is **no network,
  no registry, no air-gap bundle, no refresh** — distribution is a later slice,
  so the loader is built behind an interface that a future slice can swap.
- **`LoadCatalog` is the only I/O.** It parses the index, then each referenced
  manifest, runs all validation (§4), builds three in-memory maps, and returns an
  immutable `*Catalog`. After load the object is read-only and side-effect-free;
  all query methods are pure.
- **No goroutines, no timers, no caching-with-TTL.** Reload = construct a new
  `*Catalog` (the refresh slice will own swap semantics; not here).
- **Placement:** flat `package main` (per CLAUDE.md), new files
  `release_catalog.go` (model + loader), `release_catalog_resolve.go`
  (resolve/lookup/derive), `release_catalog_test.go`, with a `testdata/release/`
  fixture catalog. Not wired into `controlplane.go`, any admin route, or the
  agent in this slice.

## 2. Data model

Mirrors `roadmap/D1.6d-release-management-plan.md` §6 verbatim; `schema_version`
is pinned at `1`.

### 2.1 On-disk (parsed)

```
ReleaseManifest {
    SchemaVersion  int            // must == 1
    ReleaseID      string         // opaque stable key, e.g. "rel_2026_04_v1"
    VersionID      string         // human semver, e.g. "1.4.2"
    Severity       string         // "normal" | "critical"
    CreatedAt      time.Time
    Image struct {
        Repo       string         // e.g. "ghcr.io/kidcarmi/culvert"
        ListDigest string         // "sha256:<64hex>" (multi-arch manifest-LIST digest)
        Platforms  []string       // informational only
    }
    MinUpgradeFrom string         // parsed + retained; NOT enforced in this slice
    ChangelogURL   string         // retained; not fetched
    Notes          string
}

ReleaseIndex {
    SchemaVersion int             // must == 1
    GeneratedAt   time.Time
    Channels      map[string]string          // {"recommended": rel_id, "lts": rel_id, "critical": rel_id}
    Releases      []IndexEntry
}
IndexEntry { ReleaseID, VersionID, ManifestRef, ManifestSHA256 string }
```

### 2.2 Derived (in-memory, built at load)

```
Release {                          // a fully-resolved catalog record
    ReleaseID, VersionID string
    Severity   Severity            // typed enum
    Repo       string
    ListDigest string              // "sha256:<64hex>"; the agent-facing image identity
    MinUpgradeFrom, ChangelogURL, Notes string
}

Catalog {
    byReleaseID  map[string]Release
    byListDigest map[string]string // ListDigest → ReleaseID  (reverse index)
    channels     map[Channel]string // Channel → ReleaseID    (forward index)
    generatedAt  time.Time
}

type Channel string // "recommended" | "lts" | "critical"
type Severity string // "normal" | "critical"
```

### 2.3 Query results

```
ResolvedRelease { ReleaseID, VersionID string; Severity Severity; ListDigest string }
                                                // ListDigest = the value a LATER slice hands to the agent

CurrentView { Known bool; ReleaseID, VersionID string }   // !Known ⇒ unknown/custom (F6)

ReleaseView { ReleaseID, VersionID string; Severity Severity; Channels []Channel }
                                                // channel badges derived from the channel map; digest-free
```

> **Channels are pointers, not identities** (#389 §2). `recommended`/`lts`/
> `critical` are stored in the index and resolved at load into `channels`.
> **Current** and **Rollback** are *derived*, never stored — this slice derives
> Current (§3); Rollback candidates are a later slice.

## 3. APIs

Internal Go package surface — **read-only, no HTTP, no GUI, no agent client**.
All methods are pure and I/O-free after `LoadCatalog`.

| API | Direction | Contract |
|---|---|---|
| `LoadCatalog(src CatalogSource) (*Catalog, error)` | load | Parse + validate + build indexes. **Fail-closed**: any structural, enum, digest-shape, hash-binding, or dangling-pointer error returns a non-nil error and a nil `*Catalog` (no partial catalog). |
| `(*Catalog) Resolve(ch Channel) (ResolvedRelease, error)` | **forward** | Channel → release → `ListDigest`. Error if the channel is unknown or its pointer is dangling (the latter cannot occur post-load — validation rejects it — but the method is total). |
| `(*Catalog) Lookup(listDigest string) (Release, bool)` | **reverse** | Exact match of a manifest-list digest → release. `ok=false` when no release carries that list digest. |
| `(*Catalog) Current(runningDigest string) CurrentView` | derived | `Lookup` wrapper that returns `{Known:false}` (⇒ unknown/custom, F6) on no match. The caller passes the **authoritative running digest** (P1.1 `/v1/status.running_image`), **never** `upgrades.check`'s cache hint (#351 / §10 caveat). |
| `(*Catalog) List() []ReleaseView` | enumerate | All releases + channel badges + severity, **digest-free**. Deterministic order (by `VersionID`, then `ReleaseID`). |
| `(*Catalog) GeneratedAt() time.Time` | meta | The index's `generated_at`, for staleness display by a later slice. |

```
type CatalogSource interface {
    // ReadIndex returns the raw index.json bytes.
    ReadIndex() ([]byte, error)
    // ReadManifest returns the raw bytes for the manifest named by an
    // IndexEntry.ManifestRef (a bundle-relative name, NOT a path the caller
    // can escape — the local-dir impl joins it under manifests/ and rejects
    // separators / traversal).
    ReadManifest(ref string) ([]byte, error)
}
```

The only concrete `CatalogSource` in this slice is a **local directory** reader.
A registry/bundle source is a later slice and implements the same interface.

## 4. Validation rules (all fail-closed at `LoadCatalog`)

**Index:**
1. `schema_version == 1` (reject 0/absent/other).
2. `generated_at` parses as RFC 3339.
3. Every `Channels` value references a `release_id` present in `Releases`
   (**no dangling channel pointer**). Channel keys outside
   `{recommended, lts, critical}` are rejected (closed set).
4. `Releases` is non-empty; `release_id` and `version_id` non-empty and unique
   across the list (no duplicate `release_id`; no duplicate `list_digest` once
   manifests are loaded).
5. Each `IndexEntry.ManifestRef` is a bare name (no `/`, `\`, `.` traversal); the
   local-dir source joins it under `manifests/` and refuses to escape.
6. Each `IndexEntry.ManifestSHA256` is `^[0-9a-f]{64}$`.

**Manifest (per release):**
7. `schema_version == 1`.
8. **Hash binding (integrity, NOT authenticity):** `sha256(manifest bytes) ==
   IndexEntry.ManifestSHA256`. Mismatch → reject the whole load.
9. `release_id` / `version_id` equal the index entry's values (cross-consistency).
10. `version_id` matches a semver shape (`^\d+\.\d+\.\d+(?:[-+].*)?$`).
11. `severity ∈ {normal, critical}`.
12. `image.repo` is a bare repository (no `@digest`, no tag) — reuse the same
    shape rule as `config.proxy_repo` (P1.4): `^[A-Za-z0-9][A-Za-z0-9._/:-]*$`,
    no `:` after the final `/`.
13. `image.list_digest` matches `^sha256:[0-9a-f]{64}$`.
14. `created_at` parses RFC 3339. `min_upgrade_from`, if present, matches the
    semver shape (retained, **not enforced** — enforcement is a later slice).
15. Unknown/extra fields are **tolerated** (forward-compatible) but all listed
    required fields must be present and well-formed.

> **§4.8 is a content hash, not a signature.** It detects accidental corruption
> and index/manifest drift, but is **worthless against a tampering attacker**: a
> bad actor who can rewrite a manifest can rewrite its recorded `manifest_sha256`
> too. The trust anchor — a signature over the index — is a **later slice**. This
> slice MUST NOT be described or relied on as authenticated. (#389 §7.)

## 5. Failure modes

| # | Condition | Behavior |
|---|---|---|
| F1 | Index missing / unreadable / not JSON | `LoadCatalog` returns an error; nil catalog. |
| F2 | `schema_version != 1` (index or any manifest) | reject load (forward/back-compat is an explicit later concern). |
| F3 | Manifest referenced by the index is missing/unreadable | reject load (the index promised it). |
| F4 | `manifest_sha256` mismatch (§4.8) | reject load — integrity failure; surfaced as a distinct error kind so a later signing slice can layer cleanly. |
| F5 | Dangling channel pointer (channel → unknown `release_id`) | reject load (§4.3). Cannot occur at query time. |
| F6 | **Running digest maps to no release** (`Lookup`/`Current`) | NOT an error — `Current` returns `{Known:false}` ⇒ **unknown/custom**. The expected state for a locally-built or pre-catalog image. |
| F7 | **Per-arch vs list digest mismatch** | The running `RepoDigest` (P1.1) may be a per-platform descriptor while the manifest carries the manifest-**list** digest; they won't compare equal, so `Current` returns unknown. This is a **known limitation** of this slice — per-arch→list reconciliation needs a registry query and lands with the distribution slice. Documented, not fixed here. |
| F8 | Duplicate `release_id` or duplicate `list_digest` | reject load (§4.4) — a duplicate `list_digest` would make the reverse map ambiguous. |
| F9 | `manifest_ref` attempts path traversal | the local-dir source rejects it (§4.5); reject load. |
| F10 | Empty catalog (no releases) | reject load (§4.4) — an empty catalog is a configuration error, not a valid state for this slice. |

All failures are fail-closed: a bad catalog yields **no** catalog, never a partial
one a caller might resolve against.

## 6. Test matrix

| Area | Test | Asserts |
|---|---|---|
| load | happy path | valid index + manifests → non-nil catalog; maps populated; `GeneratedAt` set. |
| load | `schema_version` wrong/absent (index, manifest) | reject (F2). |
| load | manifest missing | reject (F3). |
| load | `manifest_sha256` mismatch | reject with the integrity error kind (F4). |
| load | dangling channel pointer | reject (F5). |
| load | duplicate `release_id` / duplicate `list_digest` | reject (F8). |
| load | `manifest_ref` traversal (`../x`, `a/b`) | reject (F9). |
| load | empty `releases` | reject (F10). |
| load | unknown extra field present | accepted (§4.15 forward-compat). |
| validate | bad `version_id` / `severity` / `list_digest` / `repo` shapes | each rejected with a field-specific error. |
| validate | index/manifest `release_id`·`version_id` cross-mismatch | reject (§4.9). |
| resolve | `Resolve(recommended/lts/critical)` | returns the right `ListDigest` + `VersionID` + `Severity`. |
| resolve | `Resolve(unknown channel)` | error. |
| reverse | `Lookup(known list digest)` | returns the release, `ok=true`. |
| reverse | `Lookup(unknown digest)` | `ok=false`. |
| derive | `Current(running == a release's list digest)` | `{Known:true, …}`. |
| derive | `Current(per-arch / foreign digest)` | `{Known:false}` (F6/F7). |
| enumerate | `List()` | digest-free; channel badges correct; deterministic order. |
| invariant | **no agent awareness** | package imports/needs no agent client; `ResolvedRelease` exposes only a digest, never a tag/release-id to the agent path. |
| invariant | **integrity ≠ authenticity** | a doc/test comment + a test that a hash-valid-but-unsigned catalog still loads (proving signing is not yet enforced) — guards against anyone treating §4.8 as a trust boundary. |

Determinism: `List()` order is pinned; `LoadCatalog` is deterministic for a given
source (no map-iteration order leaking into outputs).

## 7. Explicit non-goals (deferred to later slices)

This slice does **none** of the following, by design:

- **Signatures / authenticity** (#389 §7) — *no signatures yet*. §4.8 is a hash
  only; the index-signature trust anchor is a separate slice.
- **Catalog distribution / refresh** — *no network*: no registry fetch, no
  CP-hosted catalog endpoint, no polling/TTL/hot-swap. Local directory only.
- **Air-gap bundle / OVA** (#389 §8) — *no OVA work*.
- **GUI / admin API** — *no GUI*: no operator-facing surface, no release selector,
  no badges rendered. `List()` returns a view a future slice will present.
- **Agent changes & upgrade dispatch** — *no agent changes*: this slice never
  calls `upgrades.check` / `upgrades.apply` / `rollbacks`. It only **produces**
  the `ListDigest` a later slice will hand to the already-shipped agent APIs.
- **CP→DP propagation** — the catalog is **not** added to `ConfigSnapshot` or
  synced to data-plane nodes.
- **Rollback candidates** (#389 §4) and **`min_upgrade_from` enforcement**
  (#389 §13 F5) — parsed/retained but not computed/enforced.
- **Per-arch → manifest-list digest reconciliation** (F7) — needs a registry
  query; lands with the distribution slice.
- **Audit** (#389 §12) — no release-level audit records here.

**Natural slice order after this one:** (1) catalog distribution + refresh →
(2) index signature verification → (3) CP→agent upgrade dispatch via `Resolve` →
(4) rollback-candidate computation → (5) GUI release selector.
