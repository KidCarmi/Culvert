# D1.3a — Backup / export design notes

**Status:** implemented in this PR. `--restore` is **not** in this slice — see D1.3b (separate, future PR).

This doc captures the on-disk contract and the CLI surface so D1.3b's restore can target the same format without ambiguity.

## CLI

```
culvert --backup /path/to/output.tar.gz
```

One-shot: writes the tarball, prints `Backup written to <path>` to stdout, exits 0. Runs **before** the global logger / proxy / gRPC stack initialize, so warnings go to stderr via `fmt.Fprintf` (matching the established `--reset-password` pattern).

Source directory is the global `dataDir` (default `/data`). No `--data-dir` flag in D1.3a; if operators need a non-default source they can chdir or use bind mounts.

## Tarball layout

```
<output>.tar.gz
├── manifest.json                   # always first entry
├── data/
│   ├── ca.bundle                   # if present
│   ├── cluster-ca.crt              # if present
│   ├── cluster-ca.key              # if present
│   ├── cluster.json                # if present
│   ├── ui_users.json               # if present
│   ├── config_versions/v*.json     # recursive
│   ├── policy.json                 # Tier 2 — if present
│   ├── policy.json.meta
│   ├── bandwidth.json
│   ├── node_groups.json
│   ├── categories.json
│   ├── category_groups.json
│   ├── blocklist.txt + .mode/.manual/.exceptions
│   ├── pac.json
│   ├── scan_exclusions.json
│   ├── alert_settings.json
│   ├── admin_settings.json
│   ├── ssl_bypass.json
│   └── dpi_patterns.json
```

## Manifest schema (`schema_version: 1`)

```json
{
  "schema_version": 1,
  "created_at": "2026-05-01T07:00:00Z",
  "culvert_version": "v1.2.3",
  "files": [
    {
      "path": "data/ca.bundle",
      "size": 1234,
      "sha256": "abc...",
      "mode": "0600",
      "required": true
    },
    ...
  ]
}
```

- `path` — tarball path. Mirrors the on-disk layout under `/data` with a `data/` prefix.
- `size` — bytes (matches the tar header's Size).
- `sha256` — hex of the file body **as packed**.
- `mode` — POSIX permission bits as a 4-digit octal string (e.g. `"0600"`).
- `required` — `true` for Tier 1 artifacts (cluster identity, RBAC), `false` for Tier 2.

Manifest entries are sorted ascending by `path` for determinism.

## Tier classification

Codified in `defaultBackupArtifacts(dataDir)` in `backup.go`.

**Tier 1 — `required: true`, all `OptionalFirstRun: true`:**
- `ca.bundle` — root CA (encrypted bundle if passphrase is set; plain PEM otherwise)
- `cluster-ca.crt`, `cluster-ca.key` — cluster CA pair
- `cluster.json` — enrolled-node roster, revoked certs, session secret
- `ui_users.json` — admin RBAC roster
- `config_versions/` — recursive (every `v*.json` in the dir)

All Tier 1 artifacts are first-run-optional in practice for Culvert: a brand-new install can be backed up before any of these are bootstrapped. Missing on disk → warning to stderr, no error.

**Tier 2 — `required: false`:**
Per-feature config files (`policy.json`, `bandwidth.json`, `node_groups.json`, `categories.json`, `category_groups.json`, blocklist + sidecars, `pac.json`, `scan_exclusions.json`, `alert_settings.json`, `admin_settings.json`, `ssl_bypass.json`, `dpi_patterns.json`, plus `policy.json.meta`).

Missing on disk → silent skip.

**Tier 3 — excluded:**
`threat_feed.json`, BadgerDB community feed, `hashcache.*`, `hit_counters.json`, `culvert.log` / `audit.log`, `update_failures/` / `update_reports/`, `updater_token.txt`, `version.txt`, `cluster_update.json`, `alert_retry_queue.json`. Regenerable, log-stream, deployment-local, or in-flight.

## Atomicity

The tarball is written to `<output>.tmp`, then `os.Rename` to the final path. On any error during pack, the `.tmp` file is removed and no `<output>` is created. Operators see a non-zero exit and a clear error message; the previous backup at `<output>` (if any) is untouched.

## Required-but-missing semantics

Two paths inside `runBackupWith`:

| State | Behavior |
|-------|----------|
| `Required: true`, `OptionalFirstRun: true`, file missing | Warning to stderr, packing continues, manifest omits the entry |
| `Required: true`, `OptionalFirstRun: false`, file missing | **Error**: `backup: required artifact(s) missing on disk: <list>`; exit non-zero; no output file created |
| `Required: false`, file missing | Silent skip |

In D1.3a's default artifact list every Tier 1 entry is first-run-optional, so the strict-error path never fires for normal usage. It's exercised by `TestBackup_MissingRequired_NotFirstRunOptional_Errors` via a synthetic artifact set.

## Test coverage (in `backup_test.go`)

- `TestBackup_Manifest_PresentAndFirst` — manifest exists and is the first tar entry; envelope fields populated.
- `TestBackup_Tier1_IncludedWhenPresent` — every Tier 1 artifact lands in the tarball when seeded.
- `TestBackup_Tier2_OnlyIncludedIfPresent` — Tier 2 files only appear when seeded; absent ones are not in the archive.
- `TestBackup_Tier3_NeverIncluded` — Tier 3 artifacts (logs, threat feed, runtime caches, updater token, version file, etc.) never appear, even when present on disk.
- `TestBackup_Manifest_ChecksumsMatchTarContents` — for every manifest entry, the body in the tar matches `size` and recomputes to the manifest's `sha256`; mode is the expected octal string.
- `TestBackup_MissingRequired_FirstRunOptional_NoError` — empty `dataDir` produces a valid tarball with `files: []` and no error.
- `TestBackup_MissingRequired_NotFirstRunOptional_Errors` — synthetic strict-required artifact missing → clear error, no output file.
- `TestBackup_ConfigVersionsRecursive` — `config_versions/` is walked recursively; every `vN.json` lands in the archive at `data/config_versions/vN.json`.

7 tests, race-clean, in-process, no subprocess, ~1s of suite cost.

## What's deferred to D1.3b

- **Restore** end-to-end: unpack, validate manifest, per-file checksum verify, schema-version probe, two-phase commit with rollback.
- **CA / trust-root restore guards:** DP-reenrollment confirmation, CA fingerprint cross-check, `ca.bundle` decrypt validation.
- **Cross-artifact consistency checks:** `cluster.json` ↔ cluster CA fingerprint, etc.
- **TOTP counter rollback guard.**
- **Restore modes:** `--mode=full|trust-root-only|state-only`.
- **`--data-dir` flag** for source path override (not needed in D1.3a; may be added if D1.3b's restore design requires it).

## What stays out of scope (for the whole D1.3 phase, restored or not)

- Online / runtime restore — restore will be offline-only.
- Auto-backup / scheduling — operator's cron job.
- Backup retention policy — same.
- Encrypted backup tarball / per-backup passphrase — operator handles encryption-at-rest.
- Network upload (S3, GCS, …) — out.
- Backup over admin API — out (CLI-only).
- Differential / incremental backups — full snapshot only.
- DP-side backup — DPs are ephemeral / re-enrollable.
- Updater / agent work — out of D1.
