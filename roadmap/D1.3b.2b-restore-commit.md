# D1.3b.2b — Restore commit path

**Status:** implemented in this PR. Closes the D1.3 backup/restore story:

| PR | What it added |
|----|---------------|
| D1.3a (#192) | `--backup` — pack /data into tar.gz with manifest |
| D1.3b.1 (#193) | `--restore` — dry-run validation (manifest, sha256, parse) |
| D1.3b.2a (#194) | Mode predicate + analyzer + guards in dry-run output |
| **D1.3b.2b (this)** | **`--confirm` — destructive commit with stage + atomic swap** |

This doc captures the commit contract.

## CLI

```
culvert --restore <path>
        [--mode {full|trust-root-only|state-only}]
        [--confirm]                              # required to commit
        [--accept-dp-reenrollment]
        [--allow-counter-rollback]
```

Behavior matrix:

| Invocation | Behavior |
|------------|----------|
| `--restore X` | Dry-run validation + analyzer plan (D1.3b.1 + D1.3b.2a) |
| `--restore X --mode=Y` | Same, with mode-aware plan |
| `--restore X --confirm` | **Destructive commit** (this PR) |
| `--restore X --confirm --accept-dp-reenrollment` | Allows CA fingerprint change |
| `--restore X --confirm --allow-counter-rollback` | Allows TOTP counter rollback |

`--confirm` is mandatory — no interactive prompt. The first invocation is always a dry-run; the operator adds `--confirm` to a second invocation to actually commit.

## Commit sequence (eight steps)

```
1. validateBackup(tarPath, dataDir, passphrase)        ← reuse D1.3b.1
2. analyzeCommit(files, dataDir, opts)                 ← reuse D1.3b.2a
3. enforce guards (DPGuardWouldBlock, TOTPGuardWouldBlock)
4. printRestoreSummary + "Committing restore now."
5. stageArtifacts(/data.staging.<ts>, /data, files, mode)
6. os.Rename(/data, /data.bak.<ts>)
7. os.Rename(/data.staging.<ts>, /data) + parent-dir fsync
8. final message — names .bak path, "(.bak is NOT auto-deleted)"
```

`<timestamp>` = `time.Now().UTC().Format("20060102T150405Z")` — single value computed once, used for both staging dir and `.bak` dir so they share a correlated suffix.

## Failure windows + recovery

| Window | On-disk state | Operator recovery |
|--------|---------------|-------------------|
| Steps 1–4 | `/data` unchanged, no staging | Re-run after fixing tarball / passing guard flags |
| Step 5 (staging) | `/data` unchanged, `os.RemoveAll(stagingDir)` runs on any error | Auto-cleanup; re-run |
| Step 5 → Step 6 boundary | `/data` unchanged, full staging dir | Auto-cleanup; re-run |
| **Between Step 6 and Step 7** | **`/data` does not exist** | **`mv /data.bak.<ts> /data`** — error message contains the exact command verbatim |
| Step 7 rename failure | Same as above | Same |
| Step 7 fsync | `/data` already restored; fsync best-effort | Success |
| Step 8 | Done | Operator may delete `.bak` if/when desired |

The 6→7 window is microseconds (two `os.Rename` calls back-to-back, no I/O between). Recovery message format:

```
restore: COMMIT INTERRUPTED — /data does not exist; manual recovery: mv /data.bak.20260502T142000Z /data ; rename staging→/data failed: <err>
```

The operator can copy/paste the `mv` line verbatim. **No auto-rollback** — matches the user's `no auto-recovery` constraint and D1.1f's "detect + fail closed" posture.

## Mode-specific staging (`stageArtifacts`)

Two-pass algorithm. Pass 1 writes tarball-sourced artifacts; Pass 2 walks current `/data` for preserved artifacts.

```
Pass 1:
    for each tarball entry path:
        if mode.fromTarball(path):  # mode says "from tarball"
            target = stagingDir + path-without-"data/"-prefix
            os.MkdirAll(target's parent)
            atomicWriteFile(target, tarball.bytes(path), 0o600)
            mark as written

Pass 2 (filepath.Walk dataDir):
    for each regular file at p (skip dirs and symlinks):
        rel = relative-to-dataDir
        tarballPath = "data/" + filepath.ToSlash(rel)
        if mode.fromTarball(tarballPath): continue  # tarball source, not preserved
        if already written: continue
        target = stagingDir + rel
        os.MkdirAll(target's parent)
        atomicWriteFile(target, os.ReadFile(p), 0o600)
        mark as written
```

**Pass 2 is critical:** it walks live `/data`, not just paths in the manifest. This addresses the PR #194 review note — files present in current `/data` but absent from the backup (e.g. config files added by features introduced after the snapshot, in non-full modes) are correctly preserved. Without this, the stager would silently lose them.

Per-mode result:

| Mode | From tarball | From current /data |
|------|--------------|---------------------|
| `full` | Every tarball artifact | None — current-only files end up in `.bak` only |
| `trust-root-only` | `ca.bundle`, `cluster-ca.crt`, `cluster-ca.key` | Everything else under live /data |
| `state-only` | Everything except the three CA artifacts | The three CA artifacts |

`atomicWriteFile` (D1.1a) handles per-file durability inside staging — file fsync + parent-dir fsync. The final atomic swap (steps 6–7) handles overall directory-level durability.

Symlinks under `/data` are skipped during pass 2, mirroring D1.3a's pack behavior.

## Guard enforcement

D1.3b.2a's `analyzeCommit` precomputes `DPGuardWouldBlock` and `TOTPGuardWouldBlock`. D1.3b.2b's commit path inspects them after analysis, before any staging:

```go
if analysis.DPGuardWouldBlock {
    return fmt.Errorf("restore: cluster CA fingerprint changes (current=... → restored=...); N DP(s) currently enrolled will need to re-enroll. Pass --accept-dp-reenrollment to proceed")
}
if analysis.TOTPGuardWouldBlock {
    return fmt.Errorf("restore: TOTP counter rollback for N user(s) (alice, bob); recently-used codes could be replayed. Pass --allow-counter-rollback to proceed")
}
```

Both guards block **before** any staging directory exists. Either failure leaves `/data` byte-identical to pre-call.

## Failure-injection seam

`var commitInjectBetweenRenames func() error` (package-level, nil in production). Tests set it via `t.Cleanup`-protected assignment to simulate process death between rename A and rename B. Used by exactly one test (`TestRestoreCommit_InjectionBetweenRenames_RecoveryMessage`); zero production cost.

## What this PR does NOT do

Per the D1.3b.2b scope decision:

- **No online restore** — operator stops culvert before running.
- **No auto-recovery** of the 6→7 window (operator runs the `mv` printed in the error).
- **No auto-delete of `.bak`.** Preserved indefinitely; operator manages disk.
- **No backup retention / cleanup** of old `.bak.<timestamp>` dirs.
- **No schema migrations** — restore still rejects `schema_version != 1`.
- **No encrypted backup tarball.** Operator's encryption-at-rest.
- **No network upload, S3, GCS.**
- **No restore over admin API.** CLI-only.
- **No DP-side restore.** DPs are ephemeral; they re-enroll.
- **No updater / agent work.**
- **No cross-version validation** beyond `schema_version`.
- **No pre/post-restore hooks.**
- **No `--stage-only` mode** (stage but don't commit).
- **No rollback validation** — does the restored `/data` actually start the proxy? Operator runs the binary post-restore.
