## D1.2-flag findings

These are pinned current behaviors, not test failures. Decisions on whether to remediate belong in D1.1h or separate scoped PRs.

### Flag 1 — `.mode` silent fallback to "block" on any non-"allow" value

`store.go:577-579` only recognizes the literal string `"allow"` (after `TrimSpace`). Anything else — including `"block"`, `"BLOCK"`, `"ALLOW"`, `"deny"`, garbage, or empty — silently leaves the mode at default `"block"`.

- **Severity:** LOW–MEDIUM. The default IS `"block"` so there's no security regression, but operator typos / accidental edits / case mistakes produce no error and no log line.
- **Pinned by:** `TestColdStart_BlocklistSidecars/mode_literal_block_silent_default`, `mode_garbage_silent_default`, `mode_uppercase_silent_default`.
- **Fix shape (deferred):** at minimum, log a warning when `.mode` is non-empty and unrecognized.

### Flag 2 — `.manual` / `.exceptions` accept arbitrary line content

Loader at `store.go:583-590` (manual) / `593-600` (exceptions) trims outer whitespace per line, skips blanks, and adds whatever's left as a literal entry. **No hostname validation.**

- **Severity:** LOW. Garbage entries never match real traffic, so no policy bypass. Also no operator visibility into what got loaded — silent acceptance of typos.
- **Pinned by:** `TestColdStart_BlocklistSidecars/manual_garbage_lines_accepted`, `exceptions_garbage_lowercased`.
- **Fix shape (deferred):** validate against a hostname regex; either skip-and-log invalid entries or fail closed.

### Flag 3 — `listConfigVersions` silently skips corrupted files

`configversion.go:185-194` walks `configVersionsDir`, reads each `vN.json`, and silently `continue`s past any file it cannot read or unmarshal. The operator-facing list returns successfully without those entries.

- **Severity:** MEDIUM. An operator using `/api/config/versions` to recover from a problem sees no indication that vN exists on disk but is unusable. Combined with the D1.0 flag that `saveConfigVersion`'s writer was non-atomic (fixed in D1.1a), a partial historical write could be silently invisible from the rollback UI.
- **Pinned by:** `TestColdStart_ConfigVersions_List_CorruptedFileSilentlySkipped`.
- **Fix shape (deferred):** include corrupted entries in the list with a `status: "corrupted"` marker, OR log per-skip at warn level.

### Flag 4 — `bandwidth.json` / `node_groups.json` policies with missing required fields silently load as zero values

`json.Unmarshal` fills missing struct fields with zero values. A bandwidth policy with no `name` and no `label_selector` loads as a zero-name match-nothing policy; same for node groups. The loader does no validation.

- **Severity:** LOW. The admin API may validate elsewhere (separate concern), but a hand-edited or restored-from-bad-backup file bypasses that path.
- **Pinned by:** `TestColdStart_Bandwidth_Cases/missing_required_fields`, `TestColdStart_NodeGroups_Cases/missing_required_fields`.
- **Fix shape (deferred):** validate `Name` non-empty and `LabelSelector` non-nil at load time; skip-and-log invalid entries.

## Subtle but expected behaviors pinned

- **`bandwidth.json` `{}`** triggers `"failed to parse"` log (cannot unmarshal object into slice) and resets `m.policies` to nil — pinned in `empty_object` subtests.
- **`node_groups.json`** mirrors the same shape. Constructor's nil-check (`nodegroup.go:52-54`) promotes nil back to an empty slice.
- **Unknown JSON fields** are tolerated (Go's json package ignores them by default) — pinned in `valid_with_unknown_field` subtests for both bandwidth and node groups.
- **`config_versions/vN.json` envelope without `config` field** loads cleanly with a zero-value `configBackup` — no error. Pinned in `envelope_missing_config_field`.

## D1.1h prioritization input

The full D1.2 matrix (D1.2a + D1.2b) shows:

- **Cluster-CA path is well-defended** — D1.1f cross-validation + D1.1g atomic-write pair already handle every bad-state case D1.2 surfaced. **No `.bak` recovery needed for the cluster CA**.
- **`ca.bundle` is well-defended** — fails closed on every bad-state case except the D1.2a-flagged "plain-PEM-with-passphrase" compatibility behavior, which is informational only.
- **`ui_users.json` missing-file is silent** (D1.2a Flag) — strongest candidate for a behavior change in D1.1h or a dedicated RBAC slice.
- **The four `.mode` / sidecar / list-skip / missing-field findings (D1.2b Flags 1–4)** are LOW-MEDIUM and converge on a common pattern: silent acceptance of operator/file errors. Could be addressed by a small "validation + warn-on-skip" sweep across loaders, independent of `.bak` recovery.

`.bak` fallback recovery (the original D1.1h pitch) is harder to justify after this matrix — most artifacts already fail closed cleanly. The bigger lever is **observability of silent fallbacks**, not auto-recovery.
